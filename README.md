# 데이트메이트

**지역·시간·예산·취향을 바탕으로 전국 데이트 코스를 추천하고, 그날 그 지역의 축제까지 함께 보여주는 웹 서비스**입니다. 장소 사진과 블로그 검색 결과, 예상 비용, 이동 정보를 한 화면에서 확인할 수 있습니다.

> 다른 컴퓨터에서 클론해 바로 이어서 작업하려면 [배포-이어가기.txt](배포-이어가기.txt)를 먼저 보세요.

## 주요 기능

- **맞춤 코스 추천**: 꼭 정할 것은 지역 하나입니다. 인기 동네 칩이나 "현재 위치"로 한 번에 고르고, 목록에 없는 곳은 "데이트할 지역" 칸에서 동네·역·주소를 바로 검색하거나 "지도에서 고르기"로 고릅니다. 현재 위치는 브라우저가 알려 주는 오차가 크면 그대로 쓰지 않고 오차를 알린 뒤 확인을 받습니다. 날짜·시간·예산·인원·장소 수·교통은 기본값이 요약 한 줄로 보이고 "바꾸기"에서 칩이나 "직접" 입력으로 고치며, 칩을 누르면 정해진 값을 그 자리에서 알려 줍니다. 예산은 "예산 무관"으로 둘 수 있습니다. 음식 위주로 요청하지 않았다면 한 코스에 식당은 식사 시간대마다 1곳까지만 들어갑니다. 다시 방문하면 "지난번처럼 추천" 한 번으로 같은 조건을 쓸 수 있습니다. 실제 장소 코스는 전국 17개 시·도 중 선택한 시·도 안의 장소만 사용합니다. 가상 장소 데모는 서울만 지원합니다. 이미 지난 방문일이나, 오늘인데 종료 시각이 지난 요청은 안내와 함께 거절합니다.
- **축제 연계**: 코스를 추천받으면 같은 지역·같은 방문일에 열리는 축제·행사를 결과 화면에 함께 보여줍니다(한국관광공사 자료, 사진 포함). 출발지에서 가까운 순으로 정렬하고 직선거리를 표시하며, "이 축제 주변 코스 추천받기"로 그 축제 위치를 기준으로 다시 추천받을 수 있습니다. 축제 카드에서 불러 둔 운영 시간(예: `10:00~18:00`)이 코스 시작 시간과 맞으면 축제 방문을 일정 맨 앞에 고정하고 나머지 장소를 그 뒤로 배치합니다. 개막이 늦은 저녁 축제는 장소를 돈 뒤 축제로 마무리하고, 앞도 끝도 맞지 않는 낮 축제(예: 11:30~13:00, 코스는 오전부터 저녁까지)는 두 장소 사이에 행사장을 들러 축제를 보고 다음 장소로 가는 코스로 짭니다. 시간을 모르거나 맞출 수 없으면 코스는 그대로 두고 조건 확인에 까닭과 바꿀 시간을 안내합니다. 축제 카드의 「+ 내 코스에 추가」는 이미 만든 코스(출발지·장소 그대로)에 그 축제 방문을 끼워 넣습니다: 서버가 관광공사 목록·상세의 좌표·기간·운영 시간으로 코스 끝이나 장소 사이 자리를 정하고, 미리보기에서 어디에·몇 시에 들르는지와 바뀌는 시간·비용·도보를 본 뒤 확정합니다(되돌리기 가능). 운영 시간을 모르거나 방문일이 기간 밖이거나 넣을 자리가 없으면 까닭을 알리고 넣지 않습니다.
- **대안 비교**: 최대 3개 코스를 비교합니다. 가능하면 하루 구성(식사·카페·전시·산책·체험)이 서로 다른 안부터 고르고, 코스마다 실제 차이에서 붙인 서로 다른 이름("기준 코스", "산책 넣은 코스" 등)과 코스 1과의 차이를 보여줍니다. 장소 고정·교체·되돌리기를 지원하고, 후보가 부족하면 조건을 단계적으로 넓혀 찾고 변경 사항을 표시합니다.
- **늦어졌을 때**: 코스 상세의 「늦어지면 어디서 문제가 생길까?」에 남은 첫 장소와 늦는 분을 넣으면 남은 일정이 영업시간·휴무·축제 시간과 어디서 어긋나는지 보여 줍니다. 늦어서 맞출 수 없게 된 장소가 있으면 그 자리에서 같은 종류의 대신 갈 곳(코스를 만들 때 찾아 둔 동네 후보에서만, 최대 3곳)이나 '빼고 진행'을 고를 수 있고, 누르면 지연을 반영해 남은 시간표를 다시 짠 새 코스로 저장합니다(되돌리기 가능). 바꿔도 뒤 장소 한 곳이 또 늦으면 그 장소까지 함께 바꾸거나 뺀 안을 한 번에 고를 수 있고, 그렇게 고친 코스에서 수단이나 다른 장소를 바꾸거나 식사를 넣거나 합의 코스를 만들어도 반영한 지연은 그대로 남습니다(합의 코스에서 늦은 장소가 빠지면 그 지연은 넣지 않고 그렇다고 알립니다). 예약한 곳은 바꾸지 않고 예약처 연락을 안내합니다.
- **순서 제안**: 코스 상세의 「순서를 바꾸면 이동이 줄어들까?」를 펼치면 같은 장소를 다른 순서로 돌 때 이동이 5분 이상 줄어드는지 계산해, 가장 많이 줄어드는 순서 하나를 제안합니다. 고정했거나 예약한 장소는 제자리에 두고 영업시간·종료 시각을 지키는 순서만 보며, 지금 순서와 새 순서를 같은 추정 방식으로 견줍니다. 누르면 새 코스로 저장합니다(되돌리기 가능). 펼칠 때마다 다시 계산하고, 같은 코스에서 장소 고정을 바꾸거나 제보를 저장해 화면이 다시 그려져도 이 상자와 지각 확인 상자는 열린 상태·입력·결과를 유지합니다(고정이 바뀌었으면 같은 입력으로 다시 확인).
- **구간별 이동 수단**: 일정의 구간마다 도보·대중교통·자동차·자전거를 바꿀 수 있고, 그 코스만 다시 계산합니다. 장소나 수단을 바꾸면 예상 비용을 "바꾸기 전 → 후" 범위로 보여줍니다. 대중교통 구간 시간은 지하철·버스를 구분하지 않은 추정이며 화면에 그렇게 표시합니다.
- **네이버 지도 길찾기 연결**: 일정의 구간 줄마다 「네이버 지도 대중교통 길찾기 ↗」(자동차·도보 구간은 「네이버 지도 길찾기 ↗」)가 있어, 출발·도착이 채워진 네이버 지도 길찾기를 새 탭으로 엽니다. 지하철·버스 노선·환승·요금·실시간 도착은 네이버에서 확인합니다(네이버 지도 API 에는 공개된 대중교통 길찾기가 없어 앱 안에서는 추정 시간만 보여 줍니다). 2026-11-19 이전의 TMAP 「지하철·버스 비교하기」를 대신합니다.
- **장소 둘러보기**: 시·도와 활동을 고르거나 검색어를 넣으면 공공 자료(한국관광공사 목록, 동네 검색어가 있으면 그 주변 소상공인 상가정보)를 사진 있는 곳부터 보여줍니다. 그 아래 접힌 '네이버에서 더 찾기'를 펼치면 검색어마다 네이버 지역 검색 결과를 받은 순서 그대로 블록으로 보여줍니다(합치거나 다시 줄 세우지 않음). 전체 인기순·평점순 목록은 아닙니다.
- **테마별 시작(2026-11-24 2트랙)**: 「테마로 고르는 하루」가 두 탭입니다. 「오늘의 상황으로 고르기」는 이번 달 계절 카드 1장과 상황 테마 6장(비·더위 실내, 썸·소개팅, 이색 액티비티, 퇴근 후 3시간, 기념일, 최소 도보 힐링)으로, 고른 지역은 그대로 두고 실내외·도보 제한·시간대·장소 수·예약·분류 같은 조건만 채웁니다. 「주말 떠나기 좋은 동네」는 서울 성수·부산 광안리·해운대·강원 강릉·경북 경주·제주 애월 5곳으로 지역·분위기·이동 수단을 채웁니다. 다른 테마로 바꾸면 이전 테마 조건을 고르기 전 값으로 되돌린 뒤 새로 채우고, [테마 해제]로 처음 상태로 돌아갑니다(`datemate/static/theme-cards.js`). 카드가 넣은 분위기는 우선순위로만 쓰고, 사용자가 직접 고른 분류만 후보를 거릅니다.
- **코스 지도**: 네이버 지도(키가 없으면 Leaflet/OpenStreetMap 대체 지도)에 출발·장소 번호·귀가와 이동 구간, 주변 식당·주차장·축제·팝업을 표시합니다. 장소 번호를 누르면 일정의 그 장소 카드로 이동합니다. 휴대폰에서는 지도 표시의 누름 영역이 44px 이상입니다.
- **사진·후기·가격 근거**: 장소 사진을 좌우로 넘기고, 누르면 같은 페이지 안에서 크게 봅니다. 장소 사진은 등록 사진과 한국관광공사 사진(공공누리 제1·제3유형)이며, 대표 사진이 없는 관광공사 항목은 추가 사진 목록에서 찾고, 이름은 띄어쓰기·지역 앞말('애월')·뜻이 같은 꼬리말(해변=해수욕장) 차이를 넘어 맞추되 반경(넓은 곳 1km, 그 밖 400m) 안에 맞는 곳이 하나뿐일 때만 연결합니다. 사진이 없으면 '네이버 지도에서 사진 보기' 링크가 나오고, '사진 다시 불러오기'는 연결 실패처럼 다시 시도할 뜻이 있을 때만 보입니다([측정](datemate/docs/place-photos-measure-2026-11-20.ko.md), 2026-11-21 63번째 배포). 결과 화면 사진은 화면 근처에 올 때 받고, 카드와 레저 사진 격자에는 서버가 폭 960 WebP 로 줄인 사진(`/photo-thumb`, 우리 응답이 내보낸 주소만 허용)을 보여 줍니다. 크게 보기와 원본 링크는 원본입니다(성수 코스 측정: 사진 8장 32.3MB → 1.09MB). 네이버 블로그 검색 결과는 네이버가 준 순서·건수·제목·요약 그대로 '네이버 검색결과' 블록으로만 보여 주고 원문 링크를 붙입니다(고르거나 다듬지 않고, 추천 순위·이유 문장·가격 계산에 쓰지 않습니다). 비용은 등록된 단가와 계획용 가정 범위로만 계산하며(블로그 글의 가격은 읽지 않음), 등록 단가가 없는 곳은 가정 금액이나 미확인으로 표시하고 네이버 지도 링크를 붙입니다.
- **네이버 약관 준수(2026-11-19)**: 네이버 이용약관·robots.txt 가 금지하는 화면 자동 조회(검색 결과·플레이스·블로그 본문)를 하지 않습니다(`datemate/app/naver_pages.py`). 공식 Open API 만 쓰고, 업체가 네이버에 올린 사진·메뉴판은 앱 안에 나오지 않고 네이버 지도 링크로 안내합니다(그 뒤 2단계에서 같은 업체 확인·사진·가격도 네이버 검색 결과를 쓰지 않도록 바뀜 — 아래 항목). 검토 원문과 결정은 [datemate/docs/naver-terms-review-2026-11-19.ko.md](datemate/docs/naver-terms-review-2026-11-19.ko.md).
- **네이버 검색 API 특약 개정(2026-09) 대응 1단계(2026-11-20)**: [개정 특약](https://developers.naver.com/notice/article/33400)(NAVER API HUB 2026-09-20 시행)에 맞춰 ① 네이버 검색 데이터·파생물을 LLM 프롬프트·임베딩 색인·사진 내용 검사에 넣지 않습니다(키가 있어도 차단). ② 사용자 공용 캐시를 없애고 사용자별 보관만 최대 24시간(새 검색 시 삭제, `app/naver_cache.py`), 저장된 코스 안의 네이버 유래 값(블로그 글·가격·장소 이름·주소·좌표)은 21일 뒤 지웁니다(`app/naver_terms.py`, 마이그레이션 v0005). 브라우저에 남는 네이버 유래 출발지도 24시간 뒤 지웁니다. ③ 네이버 결과가 보이는 곳마다 '네이버 검색결과 · 원본 ↗' 표시를 붙였습니다. 다른 사용자가 같은 조건으로 찾아도 다시 조회하므로 첫 화면이 이전보다 느릴 수 있고, 21일이 지난 코스는 장소·수단 바꾸기가 막힙니다. 가공 자체가 핵심인 기능(블로그 순위 반영·가격 추출·팝업 기간 읽기·검색 사진 거르기 등)의 2단계 설계는 [datemate/docs/naver-terms-stage2-design.ko.md](datemate/docs/naver-terms-stage2-design.ko.md).
- **네이버 검색 API 특약 대응 2단계(2026-11-20, 61·62번째 배포)**: 네이버에 서면 질의를 보내고, 답이 올 때까지 가장 엄격한 읽기(검색 결과를 우리 계산의 입력으로 쓰지 않음)로 바꿨습니다. ① 추천 후보는 우리 장소 자료 + 한국관광공사 TourAPI + 소상공인 상가정보에서만 나옵니다(네이버 지역 검색은 둘러보기의 '네이버에서 더 찾기' 블록과 출발지 이름 검색에만). ② 네이버 이미지 검색 사진을 쓰지 않고, 사진이 없으면 '네이버 지도에서 사진 보기' 링크. ③ 블로그 글은 받은 그대로의 블록으로만, 추천 점수·이유 문장·가격 계산에 쓰지 않음. ④ 팝업은 블로그 글 목록 + 우리 거점 사전 지도만(기간·장소 판정 없음). ⑤ '위치' 줄의 같은 업체 확인은 상가정보·행안부 인허가(일반·휴게음식점) 판정만, 공공 API 가 느려 배경에서 조회. 대신 관광공사에 없는 동네 인기 가게, '유명 맛집 TOP 5'·리뷰순 식당, 민영 주차장, 블로그 가격이 빠졌습니다. 구현 기록은 설계 문서 5-2·5-3절, 전후 측정은 [datemate/docs/public-candidates-measure-2026-11-20.ko.md](datemate/docs/public-candidates-measure-2026-11-20.ko.md).

## 빠른 실행

Windows PowerShell / Python 3.12 기준입니다. **저장소 최상위 폴더에서** 실행하세요.

```powershell
cd datemate
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

`datemate/.env`에 사용할 API 키를 입력합니다. 기존 `.env`는 덮어쓰지 않습니다. 키 없이도 서울 가상 데이터로 시연할 수 있지만, 실제 장소 추천에는 `TOUR_API_KEY`(공공데이터포털)가, 블로그·팝업·'네이버에서 더 찾기'에는 네이버 검색 API 설정이 필요합니다.

운영(Cloudflare)에 비밀값을 넣을 때는 PowerShell 파이프(`$k | npx wrangler secret put …`)를 쓰지 마세요 — 2026-11-20 에 값이 어긋나 운영의 관광공사 호출이 반나절 실패했습니다. BOM 없는 JSON 파일(`{"TOUR_API_KEY":"…"}`)을 만들어 `npx wrangler secret bulk 파일` 로 넣고 파일은 바로 지운 뒤, 컨테이너가 다시 뜬 다음(접속 없이 약 12분) `/api/festivals?region=서울&start=…&end=…` 가 `available` 인지 확인합니다.

| 키 | 용도 | 발급처 |
| --- | --- | --- |
| `NAVER_SEARCH_CLIENT_ID`, `NAVER_SEARCH_CLIENT_SECRET` | 블로그·팝업 글, '네이버에서 더 찾기'·출발지 이름 검색(지역 검색) | NAVER API HUB의 NAVER 검색 |
| `NAVER_MAPS_KEY_ID`, `NAVER_MAPS_KEY` | 주소 검색, 자동차 길찾기 | 네이버 클라우드 플랫폼 Maps |
| `NAVER_MAPS_JS_KEY_ID` | 브라우저 네이버 지도 | 같은 콘솔의 Dynamic Map (접속 주소 등록 필요) |
| `TOUR_API_KEY` | 축제 조회 | 공공데이터포털 "한국관광공사_국문 관광정보 서비스_GW" 일반 인증키(Decoding) |

테스트까지 돌리려면 `requirements.txt` 대신 `requirements-dev.txt`를 설치하세요. `requirements.txt`는 운영 실행에 필요한 것만 담고 있습니다.

```powershell
.\.venv\Scripts\python.exe scripts/index_data.py --mode demo
.\.venv\Scripts\python.exe scripts/index_data.py --mode real
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

- 웹사이트: <http://127.0.0.1:8001>
- API 문서: <http://127.0.0.1:8001/docs>
- 기능별 연결 상태: <http://127.0.0.1:8001/api/status>
- 종료: 실행 터미널에서 `Ctrl+C`

자세한 키 설정과 키 없는 데모 실행은 [실행·설정 안내](datemate/README.md)를 참고하세요.

FastAPI 앱은 Cloudflare Containers(Workers Paid 플랜)에서 실행하고 Worker가 공개 요청을 전달합니다. 상시 실행할 개인 Docker 서버는 필요하지 않고, Docker는 배포할 이미지를 만들 때만 씁니다. 10분쯤 접속이 없으면 컨테이너가 꺼지며, 다음 첫 접속은 20~40초 걸립니다.

운영 데이터는 `DATABASE_URL`로 연결한 **Neon PostgreSQL**(무료 플랜)에 저장합니다. Cloudflare D1을 PostgreSQL 대신 설정만 바꿔 연결할 수는 없습니다. 컨테이너의 Chroma 장소·문서 색인은 시작 시 다시 만들며, PostgreSQL 백업은 DB 제공자에서 별도로 설정해야 합니다.

배포하면서 확인한 내용입니다.

- **컨테이너 위치**: 처음에는 한국에서 먼 지역에 떠서 DB를 쓰는 요청이 2~3초 걸리고 축제 조회가 시간 초과로 실패했습니다. Worker가 Durable Object를 아시아(`locationHint: "apac"`)에 만들도록 바꾼 뒤 서버 처리 시간이 0.06초 수준으로 줄었습니다.
- **Secret**: `PUBLIC_ORIGIN`, `DATABASE_URL`, 네이버 검색·지도 키, `TOUR_API_KEY`를 Worker Secret으로 등록했습니다. 키는 Git·빌드 변수·이 문서에 두지 않습니다.
- **네이버 지도**: 네이버 클라우드 콘솔의 Dynamic Map Web 서비스 URL에 배포 주소를 등록해 지도 인증이 통과합니다.
- **동작 확인**: 공개 주소에서 코스 추천, 축제(요금 포함), 축제 주변 코스, 장소 둘러보기를 브라우저로 확인했습니다.
- **재배포**: 저장소 최상위에서 Docker를 켠 뒤 `npx wrangler deploy`. 새 버전은 떠 있던 컨테이너가 꺼진 뒤(10분쯤 접속이 없어야 함)에야 응답에 나옵니다. 자세한 확인 방법은 [배포-이어가기.txt](배포-이어가기.txt) 8번에 있습니다.

### 보안

배포 후 전체 보안 점검을 했습니다. 권한 우회, XSS, SQL 주입, SSRF, Git 이력의 비밀값은 발견되지 않았고, 자원 고갈과 제한 우회 문제를 고쳤습니다.

- 모든 입력에 길이 상한, 요청 본문 64KiB, 저장되는 코스 1건 300KB 상한
- 요청 제한을 세션과 접속 IP 범위(IPv6는 /64) 양쪽에 적용, IP 범위별 외부 호출 몫 제한
- 세션은 `/api/` 요청에서만 발급하고 쿠키는 `HttpOnly; Secure; SameSite=Lax`
- 공개 요청의 `/healthz`, `/readyz` 차단, 전역 잠금 대기 시간 제한

한도 이름과 기본값은 [datemate/.env.example](datemate/.env.example)의 `DATEMATE_IP_*` 항목에 있습니다. 운영에는 기본값이 적용돼 있고, 바꾸려면 `cloudflare/worker.js`가 컨테이너에 넘기는 환경변수에 추가한 뒤 재배포합니다. 같은 IP를 함께 쓰는 사용자는 한도를 나눠 씁니다.

**2차 수정(커밋 `f794796`)은 2026-11-12에 운영에 배포했습니다.** 배포 후 확인 결과와 롤백 주의점은 [배포-이어가기.txt](배포-이어가기.txt) 맨 위에 있습니다.

- 세션 토큰을 DB에 SHA-256 해시로만 저장하고 운영 쿠키 이름을 `__Host-dm_session`으로 변경. 기존 세션은 마이그레이션으로 유지되며, 이 변환은 되돌릴 수 없습니다.
- 90일 동안 이용이 없는 세션과 그 데이터를 자동 삭제(`DATEMATE_RETENTION_DAYS`). 공개 후기는 남기고 작성자 연결만 끊습니다.
- CSP에 `default-src 'self'`와 종류별 허용 출처를 추가. 실제 브라우저에서 위반 0건을 확인했습니다.
- Cloudflare Worker가 컨테이너를 깨우기 전에 IP별 요청 제한을 먼저 적용(화면·API 60초 600회, 정적 파일 1200회)
- 운영 이미지에서 `pytest`·`pypdf` 제외, CI에 Python 의존성 취약점 검사(`pip-audit`) 추가

남은 과제는 DB 앱 전용 계정 교체입니다.

운영 요청에는 출처 검사, 브라우저 스크립트 실행 정책(CSP), 세션 응답 캐시 방지가 적용됩니다. PostgreSQL 연결은 `sslmode=require`, `verify-ca`, `verify-full` 중 하나가 필수입니다. 수정 가능한 의존성 경고는 반영했고, npm 감사는 취약점 0건입니다. **ChromaDB 1.5.9에는 수정 버전이 없는 보안 공지가 남아 있습니다.** 현재 앱은 Chroma를 컨테이너 내부 `PersistentClient`로만 사용하며 Chroma HTTP 포트를 공개하지 않습니다. 해당 포트나 원격 모델 실행 기능을 추가할 때는 보안을 다시 검토해야 합니다.

배포 준비 시점 커밋 `0473e48`의 [GitHub Actions 검사](https://github.com/chogyuseong/cho-web-pj/actions/runs/43148595094)는 보안 검사, SQLite·PostgreSQL 테스트, 컨테이너 통합 검사를 모두 통과했습니다. 배포 설정과 Secret 등록 절차는 [Cloudflare 배포 안내](datemate/docs/cloudflare-deployment.md)에 있습니다.

## 데이터와 검증 범위

실제 장소와 가상 시연 데이터를 구분합니다. 축제·행사 정보와 사진은 한국관광공사 자료이며, 사진은 공공누리 제1·제3유형만 출처를 표기해 원본 그대로 보여줍니다. 개최·취소·시간·요금은 방문 전 주최 측 안내를 확인해야 합니다. 네이버 평점·방문자 수는 공식 검색 API에서 확보하지 않으며, 인기나 별점을 임의로 생성하지 않습니다. 이동 시간·비용에는 추정이 포함될 수 있고 영업시간·휴무·예약·실시간 가격을 보장하지 않습니다. 검색 사진과 블로그 원문의 권리는 각 제공자에게 있으며 출처 링크를 제공합니다.

모바일 브라우저 모의 환경에서 추천·조건 수정·옵션 전환·사진·장소 탐색·저장을 점검했습니다. 실기기와 iOS Safari 전체 검증을 완료했다는 의미는 아닙니다. 외부 API의 결과와 응답 가능 여부는 권한·네트워크·제공자 정책에 영향을 받습니다.
