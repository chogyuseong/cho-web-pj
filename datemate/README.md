# 데이트메이트 — 실행 및 설정

프로젝트 소개와 주요 기능은 [저장소 README](../README.md)를 참고하세요. 아래 명령은 `datemate` 폴더에서 실행합니다.

## 1. 환경 준비

검증 환경: Windows PowerShell, Python 3.12. 가상환경을 활성화하지 않고 Python 실행 파일을 직접 사용합니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

`requirements.txt`는 서버 실행(운영 이미지)에 필요한 패키지만 담습니다. 테스트까지 돌리거나 `scripts/`의 관리 스크립트를 쓰려면 `requirements.txt` 대신 `requirements-dev.txt`(pytest, pypdf, playwright 등 포함)를 설치합니다. 이미 가상환경과 `.env`가 있으면 재생성하지 않아도 됩니다. 공유용 `.env.example`에는 실제 키를 적지 마세요.

## 2. API 설정

기본 설정 파일은 `datemate/.env`입니다. 서버 환경변수도 사용할 수 있습니다. `DATEMATE_ENV_FILE`을 지정하면 설정 파일 경로를 변경할 수 있습니다. 키 변경 후 서버를 재시작하세요.

| 변수 | 용도 | 필요 조건 |
| --- | --- | --- |
| `NAVER_SEARCH_CLIENT_ID`, `NAVER_SEARCH_CLIENT_SECRET` | 블로그·팝업 글, '네이버에서 더 찾기'·출발지 이름 검색(추천 후보에는 쓰지 않음) | 현재 구현은 NAVER API HUB의 NAVER 검색 엔드포인트 사용. 발급 Application에서 지역·블로그 권한 활성화(이미지 검색은 2026-11-20부터 쓰지 않음) |
| `NAVER_MAPS_KEY_ID`, `NAVER_MAPS_KEY` | 주소 검색, 역지오코딩, 자동차 경로 | 해당 Maps API 사용 권한 |
| `NAVER_MAPS_JS_KEY_ID` | 브라우저 네이버 지도 | Dynamic Map 활성화 및 접속 Web 서비스 URL 등록 |
| `TOUR_API_KEY` | 축제·행사 조회, 장소 사진·영업 안내(TourAPI), 같은 업체 확인(상가정보·인허가) | 공공데이터포털 계정의 일반 인증키(Decoding) 하나. "한국관광공사_국문 관광정보 서비스_GW", "소상공인시장진흥공단_상가(상권)정보", "행정안전부_식품_일반음식점 조회서비스", "행정안전부_식품_휴게음식점 조회서비스"를 같은 계정에서 활용신청. `%`가 들어간 Encoding 키는 인증 실패 |
| `GMS_KEY` (선택) | LLM 답변·조건 해석, 후기 사진 내용 검사, 의미 임베딩(네이버 검색 결과는 넣지 않음) | `.env.example`에는 없는 선택 항목. 넣을 때만 동작 |
| `GMS_BASE_URL`, `GMS_MODEL` (선택) | GMS 연결 주소·모델 | 비우면 코드의 기본값 사용 |
| `EMBEDDING_MODE` | `demo`: 문자 해시 / `real`: 의미 임베딩 | `real` 사용 시 키·모델 권한 및 재색인 필요 |
| `EMBEDDING_MODEL` | 의미 임베딩 모델 | 계정에서 사용 가능한 모델 |

일반 NAVER Developers용 키와 NAVER API HUB용 키를 혼동하지 마세요. 현재 서버가 호출하는 API의 발급 키를 사용해야 합니다. 서버 비밀키는 브라우저에 전달하지 않으며, 지도 JS용 공개 클라이언트 ID는 브라우저에서 사용합니다.

그 밖의 타일 주소·청크 크기 등은 [.env.example](.env.example)에 있습니다. 실제 장소 코스는 전국 17개 시·도를 지원하고, 가상 장소 데모는 서울만 지원합니다.

로컬(`http://127.0.0.1:8001`, `http://localhost:8001`)에서 네이버 지도를 쓰려면 네이버 클라우드 콘솔에서 Dynamic Map의 Web 서비스 URL에 그 주소를 직접 등록해야 합니다(코드나 `.env`로는 바뀌지 않습니다). 넣은 키의 실제 동작은 `scripts/check_external_integrations.py`로 제공자별 1회씩 확인할 수 있습니다.

### 키가 없는 경우

- 실제 네이버 장소·블로그 검색은 제한됩니다. 사진은 등록 사진·한국관광공사 사진이 있는 장소만 표시됩니다.
- 네이버 지도 JS 키가 없으면 위치 선택에 Leaflet/OpenStreetMap을 사용합니다. 지도 타일에는 인터넷 연결이 필요합니다.
- `TOUR_API_KEY`가 없으면 축제 구역에 키 미설정 안내만 표시하고 코스 추천은 그대로 동작합니다. 장소 카드의 '위치' 줄은 판정 없이 네이버 지도 링크만 나옵니다.
- GMS 키가 없으면 규칙 기반 답변을 사용하며, 실제 LLM 답변으로 표시하지 않습니다.
- GMS 키가 없거나 `PHOTO_VISUAL_CHECK=false`이면 사진 내용 검사 없이, 장소 일치가 확인된 사진(네이버 장소 ID로 묶인 사진, 장소가 설명에 명시된 후기 사진)을 '내용 미검사'로 표시합니다.
- 기본 임베딩 `demo`는 문자 bigram 해시로, 의미 임베딩이 아닙니다.
- API로 만든 가상 시연 일정은 실제 방문할 수 있는 장소가 아닙니다.

## 3. 색인 및 서버 실행

배포된 장소·문서 JSON으로 초기 색인을 생성합니다. 기본 실행을 위해 장소를 다시 수집할 필요는 없습니다.

```powershell
.\.venv\Scripts\python.exe scripts/index_data.py --mode demo
.\.venv\Scripts\python.exe scripts/index_data.py --mode real
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

<http://127.0.0.1:8001>에 접속합니다. `/docs`에서 API를 확인하고 `/api/status`에서 키·색인 상태를 확인합니다. 종료는 `Ctrl+C`입니다. 개발 중 자동 재시작이 필요하면 서버 명령 뒤에 `--reload`를 추가하세요.

의미 임베딩으로 전환했다면 `EMBEDDING_MODE=real` 설정 후 위 두 색인을 다시 만들고 서버를 재시작하세요. 해시 색인과 의미 색인은 분리합니다.

### 키 없이 API로 데모 확인

서버를 켠 상태에서 새 PowerShell 터미널에서 실행합니다. 반환되는 이름에 ‘가상’이 표시되며 실제 장소 추천이 아닙니다.

```powershell
$demoBody = @{ visit_date = (Get-Date).AddDays(1).ToString('yyyy-MM-dd'); mode = 'demo' } | ConvertTo-Json
$demo = Invoke-RestMethod -Uri 'http://127.0.0.1:8001/api/plans' -Method Post -ContentType 'application/json' -Body $demoBody
$demo.plans | Select-Object id, finish, minutes
```

일반 웹 입력 화면은 실제 장소 검색을 기본으로 합니다. 위 API 데모는 외부 키가 없는 환경에서 계산 로직을 확인하는 용도입니다.

## 4. 사용 흐름

1. 지역을 고릅니다. 인기 동네 칩이나 "현재 위치" 버튼으로 한 번에 고르고, 목록에 없는 곳은 "데이트할 지역" 칸에 동네·역·주소를 넣고 Enter 나 [검색]을 눌러 바로 아래 목록에서 고르거나, "지도에서 고르기"로 고릅니다. 시·도는 고른 위치에 맞춰 자동으로 정해집니다. "현재 위치"는 오차가 1km 를 넘으면 오차를 알리고 확인을 받습니다. 홈의 테마 카드를 눌러 지역과 분위기를 한 번에 채울 수도 있습니다.
2. 날짜·시간·예산·인원·장소 수·교통은 기본값이 요약 한 줄로 보입니다. 바꾸려면 "바꾸기"를 눌러 칩(오늘·내일·이번 토요일, 시간대, 예산 3만~15만·예산 무관)으로 고르거나 "직접"을 눌러 입력합니다. 칩을 누르면 정해진 값을 바로 아래에서 알려 줍니다. 원하는 활동은 자유 입력칸에 적습니다. 다시 방문하면 맨 위 "지난번처럼 추천"으로 같은 조건(날짜는 오늘)을 다시 쓸 수 있습니다.
3. 추천받은 최대 3개 옵션의 장소·비용·이동·조건 차이를 비교합니다. 같은 지역·방문일의 축제·행사가 결과 아래에 함께 나오며, 결과 제목 옆 버튼으로 바로 이동합니다.
4. 사진·블로그 검색 결과·메뉴 근거를 확인하고, 원하는 장소를 고정하거나 교체합니다.
5. 추천 근거와 상세 일정 사이의 **이 동선에서 즐길 레저 골라보기**에서 방문지별 항목을 펼쳐 반경 1.5km의 스포츠 후보를 확인합니다. 선택 시 해당 방문지만 교체하며 다른 방문지는 유지합니다. 고정한 장소는 먼저 해제해야 합니다.
6. 코스 카드 PNG 저장, 링크 공유 또는 인쇄/PDF로 일정을 활용합니다.
7. 불편한 점은 헤더의 "피드백" 탭(`/feedback`)에서 보냅니다. 모인 글은 `FEEDBACK_ADMIN_KEY` 를 설정했을 때만 `/feedback/admin` 에서 그 키로 볼 수 있습니다. `DATEMATE_FEEDBACK_ENABLED=0` 이면 탭과 작성 화면이 꺼집니다.

후보 부족 시 조건을 단계적으로 넓혀 찾고 차이를 표시하지만 결과를 항상 보장하지는 않습니다. 필수 조건과 제외 활동은 별도 검사합니다. 레저 후보의 거리는 직선거리이며 영업·예약 여부는 별도 확인해야 합니다.

## 5. 데이터와 한계

| 구분 | 동작과 한계 |
| --- | --- |
| 장소 | 로컬 실제 장소 자료(시드·큐레이션)와 공공 자료(한국관광공사 TourAPI 시·군·구 목록, 소상공인 상가정보 반경 조회 — `app/public_places.py`)에서 찾은 후보를 사용. 네이버 지역 검색 결과는 후보·점수·필터에 쓰지 않음. 공공 자료에는 사진·영업시간·평판이 없는 곳이 많고, 상가정보의 상호는 간판과 다를 수 있음. 가상 데이터와 분리 |
| 장소 둘러보기 | 기본 목록은 공공 자료(한국관광공사 시·도 목록, 동네 검색어가 있으면 그 주변 소상공인 상가정보)를 사진 있는 곳 먼저 정리(조건별 6시간 공용 캐시). 그 아래 '네이버에서 더 찾기'는 펼쳤을 때만 네이버 지역 검색을 검색어마다(최대 4개) 받은 순서 그대로 한 블록씩 표시(합치기·중복 제거·재정렬 없음, 사용자별 보관). 인기순·평점순 목록이 아님 |
| 주변 식당·레저·주차장 | 식당은 우리 식당 자료 + 공공 자료(관광공사에 실린 곳 먼저, 가까운 순 — 후기순 아님), 레저는 관광공사 레포츠 + 상가정보 스포츠 업종, 주차장은 공공데이터 전국주차장정보표준데이터(공영 위주)만. 민영 주차장·유명 맛집은 네이버 지도 링크로 안내 |
| 사진 | 장소 일치 여부를 비교해 검색 이미지·공개 장소 사진·일부 검수 자료 사용. 원본/썸네일 대체 및 실패 안내 제공. 코스 결과 화면 사진은 화면 600px 안에 올 때 받기 시작(인쇄 직전에는 모두 시작). 모든 장소의 사진 확보를 보장하지 않음 |
| 블로그 | 네이버 블로그 검색 결과를 받은 순서·건수·제목·요약 그대로 보여 주는 독립 블록(`app/blog_search.py`, `app/course_search.py`). 고르거나 다듬지 않고 추천 계산·가격 계산에 쓰지 않음. 전체 본문이나 방문 사실을 검증한 리뷰가 아님 |
| 비용 | 등록된 단가(업체 제공·등록 출처·운영자가 확인한 메뉴)와 계획용 가정 범위만(`app/pricing.py`). 블로그 요약의 금액은 읽지 않으며 가격을 찾는 외부 호출이 없음 |

검색 사진 없음(2026-11-20): 네이버 이미지 검색 결과에서 사진을 골라 쓰지 않습니다(검색 API 특약 2.2 — 결과를 거르거나 다시 줄 세우지 않음, `docs/naver-terms-stage2-design.ko.md` 3.4). 장소 사진은 등록 사진과 한국관광공사 사진뿐이고, 없으면 사진 칸에 '네이버 지도에서 사진 보기' 링크가 나옵니다.

한국관광공사 사진 찾기(2026-11-20 보강, `app/tour_places.py`, 2026-11-21 63번째 배포): 공공누리 제1·제3유형·관광공사 사진 호스트의 사진만 출처 줄과 함께 원본 그대로 씁니다. 관광공사 항목 번호가 있는 공공 자료 후보는 그 항목의 대표 사진을, 대표 사진이 없으면 추가 사진 목록(detailImage2, 최대 5장)을 씁니다. 카탈로그 장소는 이름으로 찾아 같은 이름(띄어쓰기·기호·지점 낱말 무시) → 없으면 느슨한 이름(주소의 시·도·시·군·구·읍·면 앞말, 해수욕장=해변=비치·전통시장=시장)의 순서로 맞추고, 반경(해변·공원·산·숲·호수처럼 넓은 곳 1km, 그 밖 400m) 안에 맞는 곳이 하나뿐일 때만 연결합니다. 부분 일치는 쓰지 않고, 음식점·카페는 관광공사 음식점과만 연결하며, 상가정보 후보는 찾지 않습니다. 찾은 결과와 추가 사진은 사용자 공용 캐시 7일, 못 찾음은 6시간, 공공 API 오류(HTTP 403, HTTP 200 + 오류 본문)는 '없음'으로 저장하지 않고 1분 뒤 다시 부릅니다. 추가 사진 호출은 관광공사 하루 상한(`DATEMATE_TOUR_CANDIDATE_CALLS_PER_DAY`) 안에서만 하고, 대표 사진이 있는 항목의 넘겨 보기용 추가 사진은 `DATEMATE_TOUR_EXTRA_PHOTOS=1` 일 때만 받습니다(기본 끔). 사진 칸의 '사진 다시 불러오기'는 연결 실패(응답의 `photo_retry`)나 사진 요청 실패 때만 보입니다. 규칙의 근거와 전후 수치는 `docs/place-photos-measure-2026-11-20.ko.md`, 테스트는 `tests/test_tour_photo_rules.py`.

같은 업체 확인(2026-11-20): 장소 카드의 '위치' 줄은 공공 자료 판정만 보여 줍니다(`app/place_identity.py`). 소상공인 상가정보에서 이름이 같은 업소가 200m 안에 한 곳이면 '위치 확인', 음식점·카페는 행정안전부 인허가(일반음식점·휴게음식점)에서 이름·도로명 주소가 같은 업소의 영업상태를 '영업 중'·'폐업으로 등록됨'으로 출처·조회 시점과 함께 적습니다. 인허가 API 는 한 번에 수십 초가 걸려 요청 중에는 부르지 않고 배경에서 조회해 저장해 두며, 판정이 없으면(자료에 없음·실패·키 없음·네이버 검색 장소) '네이버 지도에서 확인' 링크만 나옵니다. 조회 실패(키·권한 오류 포함)는 '자료에 없음'(`not_found`)이 아니라 `unavailable` 로 답하고 저장하지 않으며 30분 뒤 다시 조회합니다. 인허가 좌표(EPSG:5174) 변환은 `app/korea_tm.py`.

팝업(2026-11-20, 네이버 검색 API 특약 2단계): `/api/popups` 는 네이버 블로그 검색 한 번의 결과를 받은 순서·건수 그대로 돌려주고, 화면은 그것을 '네이버 블로그 검색 결과' 블록으로만 보여 줍니다(`app/popup_api.py`, `static/popups.js`). 글에서 기간·장소를 읽거나 글을 고르고 다시 정렬하지 않으며 사진도 붙이지 않습니다. 코스 지도의 '팝업' 표시와 '이 장소 주변 코스 추천받기'는 검색 글과 무관한 거점 사전(`app/popup_hubs.py`, 좌표는 한국관광공사 TourAPI 로 확인해 고정)만으로 그립니다.

외부로 보내는 위치: 장소·주소 검색과 자동차 길찾기는 네이버(검색어·좌표). 구간의 「네이버 지도 길찾기」 링크를 누르면 그 구간의 출발·도착 좌표와 이름(출발지가 집일 수 있음)이 담긴 네이버 지도 주소가 새 탭에서 열립니다.


## 6. 테스트

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
.\.venv\Scripts\python.exe -m pip check
```

전체 실행은 약 9분 걸리며(2026-11-13 기준 845개 통과, 1개 건너뜀) 브라우저 테스트가 포함되어 Microsoft Edge가 필요합니다. 단위/API 테스트는 임시 저장소를 사용하며 외부 검색 키를 비워 실제 검색 API 사용을 막습니다. 서버는 새 추천 요청의 지난 방문일을 거절하는데, 테스트는 과거의 고정 날짜를 쓰므로 `tests/conftest.py`가 `DATEMATE_PLANNING_NOW`로 그 검사의 현재 시각만 고정합니다. 운영에서는 이 값을 넣지 않습니다. 외부 API의 현재 응답이나 모든 장소의 정보 정확성을 보증하는 검사는 아닙니다.

브라우저 검증은 서버가 켜진 상태에서 실행합니다. Playwright는 별도 개발 도구이며 아래 스크립트는 설치된 Microsoft Edge를 사용합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install playwright
.\.venv\Scripts\python.exe scripts/check_editorial_design.py
.\.venv\Scripts\python.exe scripts/check_photo_carousel_ui.py
.\.venv\Scripts\python.exe scripts/check_leisure_results_ui.py
```

위 세 스크립트는 2026-11-13에 키 없는 로컬 서버에서 통과를 확인했습니다. `scripts/check_*.py` 중 맨 위에 `[예전 기준 점검 스크립트]`라고 적힌 것은 예전 화면·자료를 전제로 해 그대로는 실패할 수 있으며, 각 파일에 대신 볼 테스트가 적혀 있습니다. 자동 테스트(pytest)가 기준입니다.

일부 브라우저 검증은 현재 로컬 DB에 테스트 일정을 만듭니다. 모바일 모의 환경과 실제 휴대폰 검증은 구분합니다. 위 스크립트 전체를 실기기/iOS Safari 검증으로 간주하지 마세요.
