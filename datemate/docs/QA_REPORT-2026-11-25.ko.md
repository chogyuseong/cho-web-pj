## 3) 발견한 문제

### QA-01 [중간] 종료 시간이 시작보다 이르면 화면에서 막지 않고, 서버 검증 원문이 보일 수 있음 — 확인(원인 추정)
- 위치: 코스 만들기 > 시작·종료 시간
- 내용: 시작 11:00, 종료 10:00으로 제출하면 브라우저 단계에서 막지 않고 `POST /api/plan-jobs`를 보낸다(확인). 서버는 `app/models.py:138`에서 422로 거부한다. 화면의 `static/http-client.mjs`는 422 목록을 `loc: msg` 그대로 이어 붙이므로 `body: Value error, 종료 시간은 같은 날 시작 시간 이후여야 합니다.`가 토스트에 나올 것으로 추정한다(운영에서 요청을 실제로 보내는 시험은 하지 않음).
- 재현: 지역 칩 '서울 성수' → 시작 11:00 / 종료 10:00 → '3가지 맞춤 코스 비교하기'
- 수정 제안: 제출 전 검사에 start<end 추가(칸 옆 문구·aria-invalid·포커스). 422 목록에서 `Value error, ` 접두어와 `loc` 제거
- 수정 대상 파일[추정]: `datemate/static/simple-form.js` 또는 `app.js`의 제출 검사, `datemate/static/http-client.mjs`

### QA-02 [중간] 4,000자를 넘는 요청 글에 영문 개발자 오류 — 확인
- 위치: 코스 만들기 > '어떤 데이트를 꿈꾸나요?'
- 내용: textarea에 maxlength가 없다. 4,200자를 넣고 '이 마음으로 조건 채우기'를 누르면 토스트에 `text: String should have at most 4000 characters`
- 수정 제안: `textarea[name=request]`에 maxlength와 남은 글자 수 표시, 422 문구 한국어화
- 수정 대상 파일[추정]: `datemate/static/index.html:74`, `http-client.mjs`

### QA-03 [중간] 네트워크가 끊기면 'Failed to fetch' 원문 — 확인
- 위치: 첫 화면 한 줄 입력 '코스 찾기', 조건 해석
- 내용: 연결 실패 때 토스트에 브라우저 원문 `Failed to fetch`. 같은 상황에서 피드백 화면과 추천 요청은 한국어 안내를 보여 줘 화면마다 다르다.
- 재현: `window.fetch`를 실패하게 바꾼 뒤 첫 화면에 글을 쓰고 '코스 찾기'
- 수정 제안: `apiRequest`의 catch에서 `TypeError`(네트워크 실패)를 한국어 오류로 바꿔 모든 화면이 같은 문구를 쓰게
- 수정 대상 파일[추정]: `datemate/static/http-client.mjs`

### QA-04 [중간] 코스 탭을 바꾸면 키보드 포커스가 사라짐 — 확인
- 위치: 코스 결과 > 코스 1·2·3 탭(결과 목록·지도 둘 다)
- 내용: 탭 단추가 다시 그려지면서 `document.activeElement`가 BODY가 된다. 키보드·화면 읽기 사용자는 페이지 처음부터 다시 이동해야 한다.
- 수정 제안: 다시 그린 뒤 같은 코스의 탭 단추에 `focus()`
- 수정 대상 파일[추정]: `datemate/static/plan-results.js`

### QA-05 [중간] 장소 둘러보기 '더 보기' 뒤 포커스가 사라짐 — 확인
- 위치: 장소 둘러보기 > 더 보기(24곳 → 48곳)
- 수정 제안: 새로 추가된 첫 카드 제목에 `tabindex=-1` + `focus()`
- 수정 대상 파일[추정]: 둘러보기 목록 스크립트(`explore` 관련 JS)
