# 발표와 운영 배포를 구분하기

현재 운영 구성은 Cloud Run 최소 인스턴스 1 + 항상 할당 CPU + Cloud SQL이다.
백그라운드 검색과 여러 인스턴스의 일정 보존을 위한 구성으로, 무료 운영을 보장하는 설정이 아니다.

## 발표용

- 로컬 실행 또는 기존 `compose.yaml`의 단일 서버와 볼륨으로 기능을 시연한다.
- 공개 호스팅이 필요하면 공급처의 현재 요금표에서 CPU·DB·저장소·네트워크를 각각 계산한다.
- `DATEMATE_EPHEMERAL_DEMO=1`은 운영 DB 검사를 생략하는 임시 시연 모드다. SQLite를 Cloud Run에 넣으면 재시작 시 일정·피드백이 유실될 수 있다.
- 현재 검색은 백그라운드 작업이므로 최소 인스턴스 0/요청 동안만 CPU 설정을 무료 절약 팁으로 적용하지 않는다. 작업 큐와 별도 실행기로 전환하고 재시작 테스트를 먼저 해야 한다.

## 일정 보존이 필요한 운영용

`cloud-run-deployment.md`를 따른다. 실제 요금, 예산 알림, 최대 인스턴스, API 호출 제한을 배포 전에 확인한다.
예산 알림은 결제 차단 장치가 아니다. `DATEMATE_PROVIDER_CALLS_PER_HOUR`는 외부 호출 제한이며 DB·기본 인스턴스 비용을 제한하지 않는다.

배포나 결제 리소스는 이번 개선 작업에서 생성하지 않는다. 먼저 `scripts/operations_report.py`로 지연·실패·운영 출처 비율·선택 및 방문 피드백을 관찰한다.
모델 토큰 단가는 실제 계약 값으로 `DATEMATE_INPUT_USD_PER_MILLION`, `DATEMATE_OUTPUT_USD_PER_MILLION`에 설정할 수 있다. 단일 모델 기준 참고 계산이며 청구서가 아니다.
