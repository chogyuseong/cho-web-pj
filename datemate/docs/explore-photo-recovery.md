# 둘러보기 사진 누락: 원인과 수정

## 원인
1.500개 업체는 네이버 지역검색 자료다. 이미지 검색에 노출되지 않아도 해당 업체 공개 페이지에는 사진이 있었다. 브리즈밀, 우지커피 지점 등이 이에 해당했다.
2. 이미지 API 원본이HTTP라는 이유로 HTTPS썸네일까지 함께 버렸다. 도란도란 홍대입구점에서 확인했다.
3. 원본→썸네일 순차검사에서 원본 하나당 최대6초 기다렸다. 누적20초 제한으로 후속 후보가 배제될 수 있었다. 썸네일/원본 동시검사, 빠른 사진 즉시표시 후 원본으로 개선한다. 이전슬라이드의 늦은원본이 새사진을 덮어쓰지 않도록 세대토큰 사용.

## 수정
공개 검색의 PlaceDetailBase/PlaceListBusinessesItem을 이름·좌표·유일한 업체 대조 후 images/topPhotos에서 해당업체 사진만 읽는다. 메뉴판/다른업체 사진은 섞지 않는다. 공개 pstatic 이미지·출처·확인시점과 이용조건미검증 표시. 비공개API/접근차단 우회 없음.

이미지검색결과 없으면 공개업체사진으로 대체조회한다. 결과는있지만 모두표시실패한 경우에도 다른 공급경로로 복구한다. 동일 업체의 기존검색 캐시를 재사용하고 수동재시도는 서버캐시도 갱신한다. HTTPS썸네일과HTTP원본을 별도로 검증하고 HTTPS서비스에서는 HTTP이미지를 표시하지 않는다. 표시가능한 썸네일은 바로 보여주며 사용가능한 고화질원본은 뒤에 승격한다.

## 검증
동일500개 원본목록을 전수검사해 사진자료 반환474→492곳. 이전0장 업체19곳이 새로자료를 얻었으며 기존1곳의 검색결과변동도 포함한 순변화다. 최종8곳은 확인한공개업체목록의 imageCount0, imageUrl/visitorImages null. 다른장소사진으로 채우거나 모두해결됐다고 주장하지 않는다.

실제브라우저에서 브리즈밀/도란도란홍대입구점/우지커피불광중앙점 naturalWidth>0 및 가시성 확인.390px가로넘침/JS오류 없음. 제어된브라우저검사에서 느린원본을기다리지않는썸네일, 이전슬라이드늦은응답차단, 깨진원본의공개사진복구 확인. 자동테스트208개 통과.

자료: explore-photos-before.json / explore-photos-after.json. 492는 사진메타데이터 반환업체수이며500개전체원본을 모두실제디코딩한 숫자는 아니다. scripts/check_explore_photo_sources.py, check_explore_photos_ui.py, check_photo_loading_recovery_ui.py.
