## 실제 외부 연동

사용자 정보가 아닌 고정된 공개 지역과 검색어로 확인했다. 호출별 응답 내용 대신 HTTP 상태와 성공 여부만 출력하며 키는 출력하지 않았다.

| 연동 | 결과 |
|---|---|
| 네이버 지역 검색 | HTTP 200, 검색 항목 확인 |
| 네이버 이미지 검색 | HTTP 200, 검색 항목 확인 |
| 네이버 블로그 검색 | HTTP 200, 검색 항목 확인 |

| 지도 JS — 127.0.0.1:8000 | SDK 200, 지도 생성, 인증 실패 없음 |

## 실제 추천 전체 흐름

- 임시 DB·임시 색인에서 고정된 연남동 지역, 2인, 10만원, 카페·산책·식사 조건으로 실행.
- 백그라운드 작업 접수 → 실제 장소 검색 → 코스 계산 → 저장 → 완료 조회.
- 최종 성공 실행에서 **4,415ms**, 3개 코스 생성.
- 각 코스에 실제 장소 3곳, 장소 수와 일치하는 시간표, 비용 항목, 소유자 조회 성공 확인.
- 사용자 운영 DB에 점검 일정을 추가하지 않았다. 검색·지도 공급자는 실제 API를 사용했다.
- 단일 대표 조건의 실행 시간이며 평균·p95·부하 처리 능력의 측정치는 아니다.
- 의미 임베딩은 검증하지 않았다. 임시 색인은 해시 데모 임베딩으로 구성했다.

## 발견·수정

### 장소 상세의 오래된 응답이 최신 상세를 덮는 문제

첫 장소와 두 번째 장소를 연달아 열고 두 번째 응답을 먼저 반환하면, 나중에 도착한 첫 장소 응답이 모달을 덮었다. 브라우저 테스트에서 수정 전 실패를 재현했다.

`openDialog`의 세대 번호와 `showPlace` 요청 시작 시 번호를 비교해 최신 요청만 렌더링하도록 수정했다. 닫힌 모달에도 늦은 응답을 반영하지 않는다. 수정 후 관련 3개 브라우저 흐름 및 전체 242개 테스트 통과.

### 진단 도구의 Windows 파일 잠금

신규 실제 추천 진단에서 추천 자체는 성공했으나 Chroma의 메모리 매핑 파일 때문에 임시 폴더 정리가 실패했다. 별도 작업 프로세스가 종료된 뒤 부모가 임시 폴더를 정리하도록 수정하고 정상 종료를 확인했다. 서비스 추천 실패와 진단 정리 실패를 구분했다.

## 재실행

`datemate` 폴더에서:

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe scripts/check_cloud_runtime.py
.\.venv\Scripts\python.exe scripts/check_external_integrations.py --llm-call
.\.venv\Scripts\python.exe scripts/check_real_course.py
.\.venv\Scripts\python.exe scripts/inspect_plan_assets.py --network --refresh --live --map-probe
```

외부 연동 명령은 설정된 실제 키로 소량 요청한다. `--llm-call`은 키가 설정된 경우 고정 문장·최대 completion 32토큰으로 1회 요청하며, 미설정이면 실행하지 않는다. 마지막 자산 진단은 운영 일정을 읽고 공개 자료 캐시를 갱신하지만 사용자 일정·후기를 생성·삭제하지 않는다.
