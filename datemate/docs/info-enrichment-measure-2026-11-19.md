# 정보 한 건 보강이 코스 선택을 바꾸는가 (2026-11-19 측정)

[DateMate에서 다음에 만들 것](product-priorities-deep-review.ko.md) 3번의 측정이다. 재현: `python scripts/measure_info_enrichment.py`(datemate 폴더, 외부 호출 없음), 회귀 테스트 `tests/test_info_enrichment_measure.py`.

## 방법

- 한 동네(서울 성수, 출발 성수역, 도보, 방문일 2026-11-20 금) 고정 후보로 세 상황을 만든다: **A 퇴근 후 마감 직전 전시**(18:40~21:30, 문화·예술), **B 두 사람 전체 예산 5만 원**(필수 조건), **C 비 오는 날 실내 활동**(실내 필수).
- 각 상황을 자료가 충분한 경우와, 같은 후보에서 의사결정 필드가 빠진 경우로 돌린다. 추천은 기존 추천기 `app.planner.recommend` 를 그대로 쓰고 후보 풀만 고정한다(`allow_estimates=True`, 즉 모르는 영업시간은 '미확인'으로 표시하고 하루 종일로 가정하는 현재 동작).
- 후보·요청·방문 시각을 고정한 채 필드 하나만 채워 다시 돌린다. 기록 항목: 원래 조건을 지킨 코스 수, 완화한 조건, 선택을 보류하게 만드는 미확인 항목.
- 판단 규칙: 원래 조건을 지킨 코스가 있고 그 상황의 결정 필드(A 영업시간, B 가격, C 실내·영업시간·휴무)가 미확인으로 남지 않으면 **선택 가능**, 결정 필드가 미확인이면 **보류**, 코스가 없으면 **코스 없음**.
- '원래 조건'에서 `stay_minutes`(요청한 장소당 60분과 장소 자료의 체류 시간 차이)는 사용자가 정한 조건이 아니라 장소 자료라서 제외했다. 모든 사례에 이 차이가 붙어 있었다.

## 읽은 것

- **보강이 판단을 바꾼 사례 7건 중 3건은 '갈 수 없는 코스가 정확히 빠진' 경우다.** A 자료 부족 2(입장 마감 18:30 스튜디오의 영업시간이 빠지면 18:40 출발 뒤 '북카페 → 스튜디오'가 나옴), B 자료 부족·자료 부족 2(가격 모르는 공방이 든 '공방 → 비스트로', 실제 64,000원이 예산 안 코스로 나옴). 보강 뒤 이 코스들은 사라졌다.
- **A 자료 부족(gallery)은 순서가 바뀌었다.** 영업시간을 모를 때는 '북카페 → 전시관' 순서였는데 실제 마지막 입장 19:30 이면 그 순서로는 입장할 수 없다. 보강 뒤 '전시관 → 북카페'로 바뀌었다.
- **C 자료 부족(tea)은 실내 여부를 모르는 찻집이 비 오는 날 후보에서 빠져 코스가 0개였다.** 실내로 확인하자 코스가 생겼다. 여기서는 '보류'가 아니라 '없음'으로 보이므로 사용자는 자료 부족인지 조건이 너무 좁은지 구분할 수 없다.
- **결정과 무관한 필드만 채우면 판단이 바뀌지 않는다**(A 자료 부족 3: 영업시간이 빠진 채 가격만 채움 → 계속 보류).
- 현재 동작에서 **가격을 모르는 장소는 예산 필수 조건을 '원래 조건 충족'으로 통과한다**(B 자료 부족의 '원래 조건 3'). 화면은 가격 미확인을 표시하지만, 예산을 꼭 지켜야 하는 사용자에게는 보강 전 코스가 확정처럼 보일 수 있다. 다음 개선 후보로 기록한다(이번에는 동작을 바꾸지 않았다).

## 범위

- 장소 이름과 값은 시험용으로 만든 고정 후보다. 실제 장소의 자료 보유율, 서비스 전체에서 '선택 가능' 비율, 실제 장소 정확도로 옮겨 말할 수 없다.
- 과거 입력 해석 테스트(`input-combinations-10000-final.json`)의 통과 건수는 입력 해석·정규화의 결과이며 이 측정과 모집단이 다르다. 환산하지 않는다.
- 이동 시간은 저장소의 거리 기반 도보 추정이다. 사람이 공식 안내로 확인한 결과는 없다(자동 판정만).
