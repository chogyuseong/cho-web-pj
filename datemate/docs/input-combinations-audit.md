# 입력 조합 10,000개 검증 및 코스 생성 추가 검증

점검일: 2026-10-23. 실제 실행 폴더: `C:\Users\SSAFY\Desktop\새 폴더\cho-web-pj\datemate`, 화면 확인 주소: `http://127.0.0.1:8000`.

## 점검 범위와 결과

| 대상 | 입력 수 | 통과 | 점검 방법 |
|---|---:|---:|---|
| ‘어떤 하루를 원하세요?’ | 5,000 | 5,000 | 로컬 HTTP 조건 해석 API + 모델 정규화. 활동·제외 유형·인원·예산·방문 수·실내외 대조 |
| ‘이 일정에 대해 물어보세요’ | 5,000 | 5,000 | 로컬 HTTP 일정 질문 API. 저장된 가상 일정에 비용·이동·주소·주의·날씨·메뉴·예약·식사·주차·변경 질문 |
| 위 조건 입력의 코스 생성 추가 검사 | 같은 5,000개 | 5,000 | 로컬 HTTP `/api/plans`. 통제된 후보 장소와 제외 후보를 주고 실제 추천 엔진·조건 전달·일정 저장 검증 |

고유 입력은 총 **10,000개**다. 코스 생성 검사는 그중 조건 입력 5,000개를 추가 검증한 것으로 별도의 5,000개 고유 입력으로 합산하지 않는다.

조건 입력은 서울 25개 구 × 활동 10종 × 표현 5종 × 숫자 조건 4종으로 생성했다. 인원에는 2·3·11·20명, 방문 수에는 2~5곳을 포함한다. 질문은 25개 질문 접두어 × 주제 10종 × 표현 5종 × 문장 형식 4종이다. 이 중 영어 질문 표현도 포함한다. 10,000개의 조합이 10,000개의 독립적인 의도나 실제 사용자 설문을 뜻하지는 않는다.

## 발견한 문제와 수정

- ‘○○는 안 좋아해’, ‘별로야’, ‘좋아하지 않아’, ‘못 마셔’ 등의 제외 표현을 인식하도록 보완했다.
- ‘몇 분 걸려?’, ‘차로 가면?’ 등 구어체 이동 질문을 일정 시간·도보/자가용 비교로 연결했다.
- 주차·식사·메뉴·예약·날씨 질문에 주제와 관계없는 조건 차이만 나열하거나 검색으로 넘기는 경우를 보완했다.
- 확인되지 않은 주차·메뉴·날씨는 확인되지 않았다고 답한다. 실제 주차 가능 여부·메뉴·날씨를 생성하지 않는다.
- 영어 비용·이동·주소·주의·날씨·메뉴·예약·식당·주차·변경 표현을 저장 일정의 대응 질문에 연결했다.
- 변경 질문은 변경 버튼으로 안내하며 일정 자체를 자동으로 바꾸지 않는다.
- 반복 요청 뒤 SQLite 연결이 남아 테스트 DB 파일 정리가 실패하는 문제를 발견했다. 트랜잭션 종료 후 연결을 닫도록 수정하고 롤백·연결 종료 테스트를 추가했다.

초기 검사에서는 5,300개가 정해 둔 기준을 통과했다. 기준 미통과에는 누락·주제와 다른 답변·불충분한 안내 등이 포함되며, 나머지 4,700개가 모두 서버 오류였다는 뜻은 아니다. 수정 후 동일한 10,000개가 기준을 통과했다. 답변 자연스러움·추천 만족도를 사람 평가로 측정한 점수는 아니다.

## 전원 종료 후 재개

10,000개 해석·질문 결과는 종료 전에 저장돼 있었다. 코스 생성 검사는 완료된 4,327개를 검증한 뒤, 미완료 673개만 이어서 실행했다. 네 구간의 입력을 합쳐 중복 없이 5,000개이며 원래 조건 입력 전체와 일치함을 확인했다. 생성 테스트는 매 사례 결과를 즉시 기록하고 `--resume`으로 재개한다. 마지막 기록이 전원 종료로 잘렸다면 완전한 기록까지 유지하고 해당 사례를 다시 검사한다.

## 실제 화면 확인

실제 네이버 주소 검색으로 종로구를 선택하고 ‘카페 투어 하고 싶어. 볼링은 안 좋아해. 2명 10만원 3곳’을 제출했다. 제외 표현 인식과 인원·예산 반영을 확인했다. 이어서 10개 주제의 질문을 화면에 직접 제출해 답변 유형을 확인했다. 저장된 일정 URL로 재접속하여 대화 이력을 확인했고, 390px 화면에서 가로 넘침·JavaScript 오류가 없었다. 질문 중 일정 자동 변경도 발생하지 않았다.

## 한계

- 대량 검사는 격리된 임시 DB를 사용한다. 실제 사용자 대화·일정은 대량 생성 데이터로 채우지 않았다.
- 외부 LLM·네이버 검색·이미지 API를 10,000번 호출하지 않았다. 질문의 외부 LLM 대체 경로는 테스트용 응답으로 막고 저장 일정 응답을 검사했다.
- 코스 생성 5,000개 검사는 ‘real’ 코드 경로를 사용하지만 후보는 자동 검사 전용 가상 장소다. 검색·장소 발견·가격 조회 공급자는 테스트용 자료로 대체했다. 실제 추천 엔진과 저장 처리는 그대로 실행했다.
- 따라서 서울 모든 장소의 실시간 영업·가격·사진·리뷰 품질이나 네이버 장애 상황을 10,000개 입력으로 검증했다는 의미가 아니다.
- ‘메뉴·주차·날씨 미확인’이라고 정확하게 안내한 경우도 통과에 포함한다. 모든 질문에 구체적인 실제 메뉴·주차장·예보를 제공한다는 의미가 아니다.

## 재현 및 결과 파일

- `python scripts/check_10000_inputs.py --label final`: 조건 해석·일정 질문 10,000개. 유료 API 호출 없음.
- `python scripts/check_5000_recommendations.py --limit 1250 --offset 0 --resume`: 첫 구간 재개. 나머지 offset은 1250·2500·3750.
- `python scripts/summarize_input_audit.py`: 4개 구간 중복·누락 검증 및 합산.
- `scripts/check_mass_input_samples_ui.py`: 실행 중인 8000번 서버에서 실제 화면 점검. 네이버 주소 검색 및 실제 추천 호출 포함.
- `input-combinations-10000-baseline.json`, `input-combinations-10000-final.json`: 전후 요약.
- `input-combinations-10000-*.jsonl`: 생성 입력·예상값·검사 결과 전체.
- `recommendation-matrix-5000.json`, `recommendation-matrix-5000.jsonl`: 코스 생성 추가 검사 요약·개별 결과.
