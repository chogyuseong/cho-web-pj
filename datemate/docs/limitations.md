# 남은 범위 및 문제 해결 기록

## 아직 검증할 수 없는 외부 연동

1. GMS_KEY 미발급: 비워 둠. 실제 LLM, 의미 임베딩, 전문가 검색어/선별 프롬프트 실호출, RAG 전후 5문항 평가 미실행. 코드 경로·파싱·키 없음·데모 동작은 로컬 검증.
2. 네이버 Maps 서버/JS 키 없음: 자동차 경로 어댑터와 실제 장소 지도 로더는 구현했지만 실호출 미검증. 도보·대중교통·자전거의 서버 실제 경로 공급자는 미연결. 앱 링크만 제공.
3. 실제 운영정보 미완비: 152곳의 명칭·유형·좌표가 있어도 요금·영업시간·예외 휴무·예약을 확인한 것이 아님. 실제 모드의 일정 생성은 데이터/경로 부족으로 제한. 키만 넣으면 실제 일정이 완성된다고 주장하지 않음.
4. 미디어·외부 평점 공급자 계약/권리 미확보: 현재 0건. 개수나 순위를 만들지 않으며 검색 더보기 링크와 빈 상태를 제공.
5. 원본 과제 PDF 미첨부: 지정 버전 및 공식 NF 번호 대조 미검증. 기존 실습 버전은 건드리지 않고 별도 설치 가능한 버전을 사용. 전체 설치 결과 `requirements.lock.txt`.

## 구현상 제한

- 자연어 파서는 예산·테마·장소 수 일부만 해석. 기타 요청 전체의 구조화는 미구현. UI에서 필수 조건을 직접 확인해야 함.
- 시간 모델은 같은 날, 하나의 영업 시간대와 휴식 구간. 복수 영업시간·공휴일/예외일·날짜별 가격·단체/무료 적용 조건의 일반 정규화는 후속 확장. 실제 데이터에 이를 추측해 채우지 않음.
- 빔 탐색은 최적/전수 탐색 아님. 선택 장소 집합을 바꾼 최대 3개지만 고도화된 취향 다양성 모델은 없음.
- 주차비/대여비/환승 정보는 실자료 미연결. 확인 필요로 유지. 경로 비용 표에서 자동차 유류비+통행료는 합산 구간으로 표시하며 세부 분리 UI는 후속 작업.
- 원문 발췌 검증은 번호·부분 문자열 검사. 의미적 함의의 자동 완전 검증은 없음. 악의적인 근거에 대한 프롬프트 방어를 절대적 보장으로 주장하지 않음.
- 문서 전체 삭제에 따른 고아 청크 자동 제거와 다중 프로세스 색인 잠금은 없음. 동일 문서 갱신 청크 정리는 구현.
- 실제 후기 인증/다중 계정 방지/관리자 신고 검토 UI는 없음. 세션 고유 제약·3초 작성 제한만 적용. valid=0 운영 처리는 DB 관리로 가능.
- 서버 전체 분산 rate limit·대규모 부하/접근성 감사는 미실행. 로컬 교육용, 인터넷 공개 배포하지 않음.
- 공식 HTML 파서는 본문 외 메뉴 일부를 포함할 수 있음. 검색 품질 개선과 원문 의미 검수 필요.
- F2014 MMR 비교 미구현, F2016 다종 외부 문서 확보 미완료.

## 관찰한 문제와 대응

| 문제 | 확인 | 대응 |
|---|---|---|
| PowerShell 기본 텍스트 인코딩 | 한글 깨짐 | UTF-8 명시, JSON/HTML UTF-8 저장 |
| 기존 실습과 새 의존성 충돌 가능 | 기존 설치 목록 확인 | `datemate/.venv` 분리, 상위 requirements 보존 |
| 제한 환경 패키지 다운로드 차단 | WinError 10013 | 허용된 네트워크 설치로 재실행, pip check 통과 |
| 위키 API 접근 거절 | HTTP 403 | 우회하지 않고 실패로 기록, 공식 HTML 대체 |
| 오래된 공원 PDF 링크 | HTTP 404 | 확보 자료로 세지 않음, 새 유효 URL 필요 |
| 키 없는 검색/생성을 실제 RAG로 오인 가능 | 설계 검토 | 모드/임베딩/키 상태 상시 표시, 해시 컬렉션 분리 |
| 실제 비용/운영정보 누락 | 데이터 검토 | null 유지, 검증된 일정 생성 제한 |
| Chroma 청크 갱신 후 검색 오류 | 선택 장소 청크 수보다 큰 n_results에서 HNSW 오류 재현 | 필터 결과 수를 먼저 조회해 Top-k를 제한, 회귀 테스트 통과 |
| Windows .js MIME 매핑 | text/plain + nosniff로 스크립트 실행 차단 | 서버에서 text/javascript 명시, MIME 회귀 검사 추가 |

추가 결과를 받으면 공식 운영정보 검수 → 실제 의미 색인 → 실제 경로 확인 → RAG 전후 평가 순서로 이어갈 수 있다. 지금 생성된 결과를 실제 예약·방문 가능 일정으로 사용하지 않는다.
