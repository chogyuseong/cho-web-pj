# 출발지·귀가지 주소 검색 / 지도 선택

2026-10-21 변경. 기존 숫자 좌표 입력을 제거하고 확정된 위치 객체만 일정 요청에 전달한다. 주소 입력은 검색어이며 결과 선택·위치 확정을 해야 좌표로 사용된다. 지도 클릭은 좌표만 확정하며 주소를 추측해 표시하지 않는다. 화면에는 ‘지도에서 선택한 출발지/귀가지’로 표시.

추가 수정: 위치 선택창을 스크롤 본문과 고정된 선택/확정 영역으로 나누어 모바일에서도 확정 버튼이 보이게 했다. 지도 선택 후 즉시 창을 닫고 다시 열 때 남은 애니메이션이 제거된 지도를 참조하던 오류도 수정했다. 실제 8000번 서버에서 위치 선택 브라우저 검증 7개 통과, JS 오류 0개. GMS 키는 상위 예제 파일에서 서비스 `.env`로 옮겼으며 값은 출력하지 않았다. GMS 실호출의 성공 여부와 네이버 주소 검색 키 설정 여부는 각각 별도다.

API: `POST /api/locations/search`, `{ "query": "서울 중구 세종대로 110" }`. 길이 2~200, 빈 공백 거부, 세션당 1초 요청 간격. 반환 `{status, message, results}`. 결과는 name, lat, lon, road_address, jibun_address. 키 누락/외부 실패/빈 결과를 각각 안내하고 임의 좌표를 만들지 않는다. 서버 키는 브라우저로 보내지 않음. 검색 주소는 로그/영구 캐시에 저장하지 않는다.

지도: 네이버 JS 키 설정 시 우선 사용. 없거나 로더 실패면 Leaflet 1.9.4 + OSM 공개 타일. Leaflet JS/CSS/LICENSE를 `static/vendor/leaflet`에 저장. 클릭·터치 및 키보드 이동 후 지도 중심 선택, 선택 마커, 명시적 확정, 취소 지원. 실제 모드 전환 시 데모 좌표 해제. 검색 결과는 textContent로 렌더링.

검증: 전체 단위/API **20개 통과**, 기존 브라우저 흐름 **6개 통과**, 신규 위치 선택 흐름 **6개 통과** (`location-tests.json`). 실제 OSM 타일 로드·출발지 클릭·귀가지 선택·모바일 넘침 없음 확인. 네이버 주소 검색은 키가 없으므로 응답 형식·주소 우선순위·좌표 매핑·외부 실패를 모의 검증했으며 실호출 성공을 주장하지 않는다.

공식 문서:
- [네이버 Geocoding](https://api.ncloud-docs.com/docs/application-maps-geocoding): 도로명/지번, x=경도/y=위도.
- [Leaflet Quick Start](https://leafletjs.com/examples/quick-start/): 지도·이벤트·타일 레이어.
- [OSM 타일 정책](https://operations.osmfoundation.org/policies/tiles/): attribution 표시, 브라우저 Referer 및 HTTP 캐시 준수, 사용자 화면에 필요한 타일만 로드. 선행/일괄 다운로드 없음. `strict-origin-when-cross-origin` 헤더 사용.

공개 타일은 가용성을 보장하지 않으며 대규모 운영용이 아니다. `MAP_TILE_URL`, `MAP_TILE_ATTRIBUTION`으로 계약한 공급자/자체 서버로 교체 가능. Nominatim 공개 API는 사용하지 않는다. 좌표→주소 역변환은 이번 변경 범위에 포함하지 않음.

변경 이전 문서에서 ‘키 없으면 지도 개략도만 제공’은 일정 동선 개략도 설명이다. 이번 출발지·귀가지 선택 창에는 키 없는 실제 OSM 지도를 추가했다. 자동차/도보 등의 실제 경로 계산 지원 범위는 그대로다.
