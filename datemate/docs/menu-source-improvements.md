# 메뉴 가격 누락 원인과 수정

## 원인
기존 파서는 공개 네이버 검색 HTML의 PlaceDetailBase→placeMenus→PlaceMenuItem 형식만 처리했다. 실제 화면에는 PlaceListBusinessesItem.menus에 가격이 있는 업체 목록, menuImages로 메뉴판만 제공하는 식당도 있었다. 따라서 지도에서 볼 수 있어도 기존 수집기에는 없는 자료로 처리됐다. 별도의 PlaceDetail_BaeminMenu는 배달 가격으로 매장 방문가격과 혼합하면 안 된다. 단순 문구 변경으로 해결하지 않았다.

## 구현
- 기존 상세 형식 유지, 식당명·좌표 대조 후 유일하게 일치하는 업체 목록 메뉴 파싱 추가.
- 문자열/숫자/사전 단가 해석. 변동·시가·가격 범위는 단일 숫자로 만들지 않는다.
- 식당 상세에 연결된 pstatic 메뉴판 이미지를 별도로 반환하고 카드 내 미리보기/전체 확대를 제공한다. 이미지 숫자를 OCR 결과처럼 생성하지 않는다.
- 배달 메뉴를 매장 메뉴 추출과 일정 단가 적용에서 제외.
- 구 이름 포함 검색에 자료가 없으면 메뉴가격 검색으로 추가 확인. 공개 접근제한을 우회하지 않는다.
- 새 parser 캐시v2로 예전 실패 캐시를 재사용하지 않음. 사용자 새로조회로 서버캐시도 다시조회.5초 재조회 제한.
- 연결 실패와 공개 가격 미확인/메뉴판만 제공하는 상태를 분리.

## 확인
소문난성수감자탕은 기존not_found에서 실제 메뉴8개(감자국식사12,000/13,000원 등), 스시도쿠 카미동 왕십리본점은 기존not_found에서 메뉴판10장으로 바뀌었다. 브라우저에서 숫자 가격4개 표시, 메뉴판 이미지 실제로드,10장 확대,390px가로넘침/JS오류 없음 확인. 별도 회귀에서 타식당/먼좌표/동일명중복/변동가격/배달메뉴 제외를 검사했다.

여전히 공개 접근이 막히거나 매장이 가격 자료를 게시하지 않았다면 현재 매장가격을 확보했다고 표시하지 않는다. 메뉴판만 있는 식당은 이미지를 보여주고, 자동 비용계산에는 확인된 숫자 단가만 사용한다.
