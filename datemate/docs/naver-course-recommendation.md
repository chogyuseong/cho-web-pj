# 네이버 코스 검색 기반 추천

식당 추천 카드의 대표 메뉴·가격은 `/api/places/{id}/menu`로 조회한다. 지역 검색 API 응답에는 메뉴가 없으므로 공개 네이버 검색 HTML에 포함된 플레이스 메뉴 데이터를 읽는다. 상호가 정확히 일치하고 등록 좌표 400m 안의 유일한 업체인지 검사한 다음, 그 업체의 `placeMenus`에서 직접 참조한 메뉴만 표시한다. 변동 가격은 숫자로 추측하지 않으며 메뉴 자료 날짜·조회 날짜·네이버 메뉴 원문을 함께 표시한다. 페이지 변경·접근 제한·업체 식별 실패 시 가격을 만들어 내지 않고 지도 확인 안내를 표시한다. 원문 HTML 전체나 이미지 파일은 저장하지 않는다.

옵션 선택 버튼에는 `Option1` 형식의 번호와 장소 분류를 바탕으로 만든 코스 요약 이름을 표시한다. 옵션을 바꾸면 원래 번호는 유지하고 선택한 코스 카드와 상세를 버튼 바로 아래로 옮긴다. 추천 근거는 선택 카드의 접힌 영역에서 확인한다. 전체 조건 확인은 불일치·방문 전 확인·추정·충족의 네 줄 요약이며 각 줄에 전체 메시지 툴팁을 제공한다. 식당 후보는 설명 옆에 사진을 보여주고 사진·장소 정보와 지도 버튼을 동일한 크기로 배치한다.

- 실제 장소 추천 요청 시 `course_query`를 검색한다. 비어 있으면 출발지 이름/대표 지역에서 검색어를 만든다.
- 네이버 블로그 검색 API의 `sort=sim`, `display=3`, `start=1` 결과를 사용한다. 네이버 통합검색 화면의 첫 세 결과와 같다는 보장은 없다.
- 네이버 공개 블로그 본문에서 읽을 수 있는 텍스트를 장소명과 대조한다. 실패하면 검색 요약만 사용하고 조회 범위를 표시한다. 로그인이나 차단을 우회하지 않는다.
- 카탈로그 장소명·검색 별칭·한국어 위키 문서 이름을 대조하고, 새 업체는 원문 상호·주소 인용과 좌표 연결 검사를 통과한 경우 후보에 추가한다. 주소를 추측하지 않는다.
- 1/2/3위 글의 기본 가중치는 3/2/1점이며 작성자 중복 제거와 작성일 가중치를 적용한다. 이 점수는 네이버 평점이 아니다.
- 조건 검증을 통과하는 조합 안에서 언급 점수를 우선한다. 일반 조건으로 검색 근거 장소가 모두 빠지면 해당 장소를 포함하는 대안을 비교하고 조건 차이를 표시한다. 피할 활동, 확인된 휴무와 운영시간, 고정 장소는 계속 검사한다.
- 검색 결과에 없는 장소로 보완한 수와 원문 링크를 표시한다. 검색 실패나 연결 가능한 장소가 없으면 기존 추천임을 표시한다.
- 검색 근거는 15분 캐시하며 조회 시각을 저장한다. 공개 본문 전체는 응답/캐시에 보관하지 않는다.

## 신규 장소·동네·식사 구성

상위 글에서 GMS 구조화 출력으로 최대 8개 장소명과 주소 인용을 추출한다. 원문에 이름·주소·연속 인용이 실제 존재하는지 코드로 재검사한다. 지역 검색에 권한이 있으면 상호·주소·좌표를 대조하며, 권한이 없으면 글에 명시된 주소를 Geocoding으로 조회한다. 주소 조회 결과가 유일한 서울 주소일 때만 추가한다. 이 경우 업체의 현재 영업 여부까지 확인된 것은 아니며 화면에 구분한다. 추출에 실패하거나 주소가 불명확하면 장소를 만들지 않는다.

연결한 장소는 7일 캐시하고 상세·사진·후기·교체에서 동일한 장소 ID를 사용한다. 같은 작성자의 반복 글은 추천 점수를 중복 가산하지 않으며, 1년보다 오래됐거나 작성일을 모르는 글은 가중치를 절반으로 줄인다. 최근 글도 현재 영업을 보증하지 않는다.

프런트엔드 기본값은 반경 2.5km, 식사 포함이다. 알려진 동네 검색어는 그 동네 중심을 사용하며, 다른 검색어는 선택한 출발지를 중심으로 표시한다. 동네 반경은 자동 완화하지 않는다. 식사 시간(11:30~14:30, 17:30~20:30)과 일정이 45분 이상 겹칠 때 식당 1곳을 해당 시간대에 30분 이상 방문하는 조합을 우선한다. 식당은 방문 장소 수·이동·체류·비용에 포함한다. 조건상 불가능하면 식사 조건 차이를 표시한다. 코스 사이의 추가 식당 후보는 별도 선택 사항이다.

자동차 최종 코스는 네이버 Directions로 다시 평가한다. 실패하면 추정 코스를 유지하며 실패 사실을 표시한다. 도보·대중교통은 실제 경로 공급자 미연결 상태이므로 직선거리 기반 추정이다.

## 아직 적용되지 않은 부분

식사 구성이 불일치하면 `/api/plans/{id}/meal-rescue`를 자동 조회해 해당 코스 인근 음식점 최대 3곳을 표시한다. 네이버 지역 검색의 `sort=comment` 순위가 높은 후보를 먼저 두고, 순위가 같으면 추가 이동이 적은 곳을 우선한다. 실제 별점이나 좋아요 수를 확보한 것은 아니다. 이미 코스에 있는 식당·동네 반경 밖 후보·피할 활동에 해당하는 후보는 제외하며, 추가 추천은 일정 시간·비용에 자동 합산하지 않는다.

사진은 화면에 붙이기 전에 로딩을 확인한다. 썸네일이 실패하면 원본 URL과 다음 사진을 시도하고, 확인 가능한 QID가 있으면 공개 대표 사진도 조회한다. 추가 사진과 상세 갤러리에도 같은 처리를 적용한다. 모두 실패하면 깨진 이미지 대신 안내·원문 링크·재시도를 제공하며, 대체 사진의 출처도 함께 바꾼다.

네이버 공식 블로그·지역 검색 응답에는 장소 별점이 없다. 현재 평점 상태는 `unavailable`이며 임의 점수나 블로그 언급 수를 네이버 평점으로 표시하지 않는다.

지역 검색이 401/403이면 NAVER API HUB 기존 Application의 NAVER 검색 > 지역 API 활성화가 필요하다. 이 권한을 활성화하면 주소가 없는 글의 업체 연결 범위도 넓힐 수 있다. 평점 순위를 추가하려면 장소 식별자, 실제 별점, 평가 수, 출처, 조회 시각을 제공하는 데이터 연결이 필요하다.
