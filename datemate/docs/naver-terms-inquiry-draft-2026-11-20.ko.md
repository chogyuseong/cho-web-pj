# 네이버 검색 API 특약 서면 질의 초안 (2026-11-20)

보낼 곳: 네이버 클라우드 플랫폼 고객지원 1:1 문의(https://www.ncloud.com/support/question). 애플리케이션은 NAVER API HUB(console.ncloud.com/naver-api-hub)에만 등록돼 있고 developers.naver.com 에는 없다(2026-11-20 사용자 확인).
적용 특약은 네이버 클라우드 공지 2243(NAVER API HUB, 2026-09-20 시행)을 기준으로 본다.
보내는 사람: API HUB 애플리케이션을 등록한 네이버 클라우드 계정 소유자.
문의 양식(2026-11-20 확인): 탭 '서비스' → 문의유형 'Application Services > NAVER API HUB' → 제목·내용(5000자) → 파일첨부(선택) → 이메일·휴대 전화번호(필수, 본인이 입력). 앱 이름·Client ID 칸은 없다. 개인 연락처는 문의 양식의 계정 정보로만 전달한다.
답을 받으면 원문을 이 폴더에 날짜와 함께 저장하고 naver-terms-stage2-design.ko.md 5-1절을 갱신한다.

## 진행 기록
- 2026-11-20: 사용자가 위 내용으로 보냄(캡처 3장 첨부).
- 2026-11-24 사용자 확인: 중간 답변만 옴 — "고객님께서 접수해 주신 문의는 현재 유관 부서에서 검토 중입니다. 확인되는 대로 신속히 안내드릴 수 있도록 하겠습니다."
  질문에 대한 답은 아직 없다(중간 답변을 받은 날짜는 기록하지 않음). 그때까지 엄격한 읽기 유지.
  이 답에 걸려 보류한 것: 블로그 글에서 휴무일을 읽어 '(블로그 참고)'로 표시하기(질문 2-3 — 질문의 예시는 팝업 운영 기간이라,
  답이 그 예시에만 맞춰 오면 휴무일은 따로 다시 물어야 할 수 있다), 받은 팝업 글 거르기(질문 1·2).
- 2026-11-24: 아래 '추가 문의' 초안을 만듦(사용자 신고 — 역삼개나리공원 블로그 후기 첫 글이 '네이버 블로그 사이트맵 - 생성 방법').
  검색어 실험(정확도순 10건): 검색어 7가지 모두 제목에 장소 이름이 든 글 0~1건 — 검색어가 아니라 그 장소를 다룬 글이 거의 없는 것.
  보낸 날짜·답은 사용자가 알려 주면 여기 적는다.
- 2026-11-24: 사용자가 '추가 문의'를 새 문의로 보냄(ncloud 고객지원 > 서비스 > Application Services(O2O_APP) > NAVER API HUB(O2O_APP_025),
  역삼개나리공원 블로그 후기 화면 첨부). 답을 받으면 질문 1·2·3 별로 허용 여부를 여기 적고 static/place-blogs.js·app/blog_search.py 를 고친다.

## 추가 문의 초안 (2026-11-24)

제목: [추가 문의] 검색 API 특약 2.2 — 장소와 무관한 블로그 검색 결과를 표시하지 않는 것의 허용 여부

안녕하세요. 2026-11-20에 검색 API 특약 2.1·2.2 해석을 문의드린 개인 개발자입니다. 기존 문의는 아직 검토 중이라고 안내받았는데, 같은 주제로 구체적인 사례가 생겨 덧붙여 여쭙니다.

상황
데이트 코스 추천 웹앱(https://datemate.guseong-family.workers.dev)에서 각 장소의 「블로그 후기」를 블로그 검색 API로 보여 주고 있습니다. 검색어는 「{장소 이름} {시·도} 방문 후기」, 정렬은 정확도순(sim), 10건이며, 특약 2.2에 따라 받은 순서·건수·제목·요약을 그대로 보여 주고 있습니다.
그런데 블로그 글이 거의 없는 장소에서는 장소와 관계없는 글이 대부분을 차지합니다. 예를 들어 「역삼개나리공원 서울 방문 후기」로 검색하면 결과 10건 중 제목에 장소 이름이 들어간 글이 하나도 없고, 첫 번째 결과는 「네이버 블로그 사이트맵 - 생성 방법」이라는 글입니다. 본문은 여러 맛집 글 링크를 모아 둔 페이지입니다(첨부 화면). 검색어를 여러 가지로 바꿔 보았지만 결과는 비슷했습니다. 사용자는 이 글을 해당 장소의 후기로 오해할 수 있습니다.

질문
1. 받은 검색 결과 10건 중 제목·요약에 장소 이름이 한 건도 들어 있지 않으면, 그 장소에서는 블로그 검색 결과 영역 전체를 보여 주지 않는 것이 허용됩니까? 결과 일부만 빼거나 순서를 바꾸지 않고, 영역 전체를 표시하지 않는 방식입니다.
2. 1이 허용되지 않는다면, 결과는 그대로 보여 주되 영역 위(검색 결과 블록 바깥)에 「이 장소를 직접 다룬 글을 찾지 못했어요」라는 안내를 두는 것은 허용됩니까?
3. 받은 결과 가운데 장소와 명백히 무관한 글(예: 다른 글 링크 모음, 「사이트맵 생성 방법」 같은 홍보 글)만 빼고 나머지를 받은 순서대로 보여 주는 것은 특약 2.2의 「선별·수정」에 해당합니까?

답변에 따라 기능을 고치려 합니다. 허용되지 않는 방식은 쓰지 않겠습니다. 감사합니다.

제목: 검색 API 특약(2026-09 개정) 2.1·2.2 해석 문의 — 검색 결과를 내부 추천 계산에 쓰는 경우

안녕하세요. NAVER API HUB 에 애플리케이션을 등록해 검색 API(지역·블로그·이미지)를 쓰는 개인 개발자입니다.
서비스는 데이트 코스 추천 웹앱(https://datemate.guseong-family.workers.dev)이며, 2026-09 개정 특약에 맞춰 AI 입력 차단, 보관 기간(개인화 24시간, 이력 21일), '네이버 검색결과' 출처·원본 링크 표시를 이미 반영했습니다.
아래 두 가지의 허용 여부를 확인 부탁드립니다.

1. 내부 계산 입력으로 쓰는 것 (특약 2.1·2.2)
   지역 검색 결과를 화면에 보여 주는 것과 별개로, 사용자가 요청한 조건(지역·시간·예산)에 맞는 코스를 만들기 위해
   검색 결과를 후보로 삼아 우리 기준(거리·영업시간 등)으로 고르고 순서를 정한 뒤, 그 장소를 출처 표시와 원본 링크와 함께 보여 줍니다.
   - 질문 1-1: 이처럼 검색 결과를 내부 후보 선정·점수 계산에 쓰는 것이 '네이버 검색결과를 제공할 목적'에 해당합니까, 아니면 금지되는 가공입니까?
   - 질문 1-2: 블로그 검색 결과에서 장소 이름이 언급된 횟수를 추천 순위 신호로 쓰는 것은 어떻습니까?

2. 블록 바깥에 다른 정보를 두는 것 (특약 2.2 '앞·뒤·중간 삽입 금지')
   네이버 검색 결과는 테두리와 '네이버 검색결과' 머리글로 구분한 블록 안에 API 필드만 받은 순서 그대로 보여 주려고 합니다.
   - 질문 2-1: 같은 카드 안이지만 블록 밖(위·아래)에 우리 정보(지도, 버튼, 우리 메뉴 정보)를 두는 것은 '삽입'입니까?
   - 질문 2-2: 블록 위에 '광고 글이 섞일 수 있어요' 같은 안내 문구를 두는 것은 어떻습니까?
   - 질문 2-3: 블로그 글 블록과 별도의 구역에, 그 글을 근거로 우리가 판단한 정보(예: 팝업스토어 운영 기간)를 보여 주는 것은 허용됩니까?

첨부: ① 둘러보기 화면(지역 검색 결과를 중복 제거해 보여 줌) ② 장소 카드(출처 표시 블록 밖에 분류 태그·'장소 자세히 보기' 버튼) ③ 팝업 글(블로그 글 아래 별도 구역에 '데이트메이트가 검색 요약에서 읽은 정보' — 질문 2-3).

답변에 따라 기능을 고치려 합니다. 허용되지 않는 부분은 공공 데이터로 대체할 계획입니다. 감사합니다.
