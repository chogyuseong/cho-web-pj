# 네이버 약관 검토와 결정 (2026-11-19)

장소 카드에 '확인 필요'(위치·영업 정보·가격)가 많다는 사용자 신고에서 시작했다. 네이버 지도 화면에서 영업시간을 읽어 채우자는 제안을 하기 전에 약관을 먼저 확인했고, 그 결과 이미 쓰고 있던 화면 자동 조회도 그만두기로 했다(사용자 결정: "최대한 단점 보완해서 추천대로 진행").

## 확인한 원문

**네이버 서비스 이용약관**(2026-10-01 시행, policy.naver.com/rules/service.html)

> 네이버의 사전 허락 없이 자동화된 수단(예: 매크로 프로그램, 로봇(봇), 스파이더, 스크래퍼 등)을 이용하여 … 네이버 서비스에 게재된 회원의 아이디(ID), 게시물 등을 수집하거나, 네이버 검색 서비스에서 특정 질의어로 검색하거나 혹은 그 검색결과에서 특정 검색결과를 선택(이른바 '클릭')하는 등 이용자(사람)의 실제 이용을 전제로 하는 네이버 서비스의 제공 취지에 부합하지 않는 방식으로 네이버 서비스를 이용하거나 … 시도해서는 안 됩니다.

**검색결과 수집에 대한 정책**(policy.naver.com/policy/search_policy.html)

> robots.txt로 보호되고 있는 데이터 베이스를 네이버의 로봇이 아닌 타 검색 로봇이 수집하는 것을 불허합니다. … 경우에 따라 저작권 침해 또는 정보통신망 이용촉진 및 정보보호에 관한 법률 등에 위반될 …

**robots.txt**(2026-11-19 조회)

| 호스트 | 모든 로봇(`User-agent: *`) |
|---|---|
| search.naver.com | `Disallow: /` (전부 금지) |
| map.naver.com | `Disallow: /`, 첫 화면(`/`, `/p/`)만 허용 |
| m.blog.naver.com | 일부 경로만 금지(본문 수집은 약관의 '게시물 수집 금지'에 해당) |
| m.place.naver.com | robots.txt 없음(조회 중 429 차단 응답을 받음). 약관 적용 |

## 결정

| 기능 | 예전 | 지금 |
|---|---|---|
| 메뉴 가격(app/menus.py) | search.naver.com 검색 결과 화면 | 공식 블로그 검색 API 요약문에 나온 가격(`blog_menu`), 없으면 네이버 지도 링크 |
| 업체 사진·업체 번호(app/public_place_photos.py) | search.naver.com·m.place.naver.com 화면 | 쓰지 않음. 등록 사진 + 한국관광공사 TourAPI 사진(공공누리 제1·제3유형, 원본 그대로 표시, 좌표 400m·같은 이름·하나뿐) |
| 블로그 글 사진(app/blog_photos.py) | 글 본문의 사진 | 쓰지 않음 |
| 코스 블로그 판정·후기 요약(app/course_search.py, app/review_facts.py) | 글 본문 | 공식 API 의 제목·요약문만 |
| 같은 업체 확인('위치' 줄) | 검색 결과 화면의 업체 번호 | 공식 지역 검색 API(app/place_identity.py: 같은 이름·400m 안·하나뿐) |
| 영업 정보 | 영업 자료 파일만 | + 한국관광공사 TourAPI 영업 안내 글(확인 시점을 몰라 '확인 필요' 유지, 일정 계산에 넣지 않음) |

스위치는 `app/naver_pages.py`(`ALLOWED = False`). 파서와 제한 로직은 네이버와 제휴해 서면 허락을 받는 경우를 위해 남겼고, 그 테스트만 `naver_pages_allowed` fixture 로 켠다. 허락 없이 켜지 않는다.

## 대신 잃는 것

- 업체가 네이버에 올린 사진이 더 이상 카드에 나오지 않는다. 관광공사에 없는 작은 가게는 사진이 없을 수 있다(사진 칸에 네이버 지도 링크가 남는다).
- 메뉴판 이미지와 전체 메뉴 목록이 없다. 블로그 요약문에 가격이 있을 때만 한두 개 보인다.
- 블로그 본문에만 장소 이름이 나오는 글은 '블로그 언급'으로 잡히지 않는다.
- 제목만 맞는 이미지 검색 결과로 사진을 채우지 않는다(다른 장소 사진이 섞이는 문제, tests/test_photo_source_priority.py).
  - 같은 날 뒤에 바뀜(사용자 피드백 "음식점 사진이 제대로 나오지 않는다"): 등록·관광공사 사진으로 2장이 안 되는 카페·미식 장소는
    공식 이미지 검색 API(약관상 허용된 공식 경로) 결과 중 제목에 가게 이름(지점 포함)과 동네·주소 낱말이 함께 나온 사진만
    '검색 사진'으로 원본·검색 링크와 함께 보여 준다. 다른 지점·다른 가게·동네 없는 제목·모음 글·다른 시·도 제목은 뺀다
    (app/image_search.strict_title_match, tests/test_strict_image_search.py). 끝내 없으면 사진 칸에 네이버 지도 링크.
  - 팝업 글 소개 옆에도 행사명·거점·'팝업'·올해가 맞는 이미지 검색 사진 한 장을 작은 칸으로 둔다(app/popup_api.post_photos).

## 남은 일

- 작은 가게의 영업시간은 여전히 대부분 없다. 근본 해결은 유료 장소 API(예: Google Places, 표시·저장 조건 검토 필요)나 업체 직접 등록.
- 공식 API 약관 7.3 ③(별도 데이터베이스 관리 금지)에 맞춰 API 결과 캐시는 짧게 둔다. 허용 기간은 여전히 확인하지 못했다(docs/popup-stage0-2026-11-14.md).
- 사진 썸네일 서버(app/photo_thumb.py)는 등록 사진과 엄격한 검색 사진의 원본(네이버 이미지·뉴스 사진 서버, 다음·카카오 사진 서버)을 줄인다.
  관광공사 사진 호스트는 넣지 않는다(제3유형 변경 금지).
