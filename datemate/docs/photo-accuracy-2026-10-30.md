# 사진 정확성 우선 정책 — 2026-10-30

## 수정

- 단독 후기의 제목이 업체명과 일치하면 무설명 본문 사진을 통째로 허용하던 경로를 제거했다. 사진별 캡션/짧은 인접 문구에 업체·지점명이 있어야 한다. 이전 문구가 맞아도 이미지 자체 설명에 다른 지점이 있으면 제외한다.
- 광고·배너·영수증·지도·쿠폰·예약화면·캡처·셀카 문구를 제외한다. 레저에서는 음식·디저트·커피 등 식사 문구도 제외한다. 로고/프로필/스티커 호스트와 GIF/SVG도 제외한다.
- `app/photo_relevance.py` 추가. 기존 GMS 이미지 입력 모델로 사진의 공간/활동/음식/광고/영수증/지도 등 내용을 분류한다. 공간·외관·활동, 식당/카페인 경우 음식만 허용한다. relevant=true·허용 분류·confidence>=0.9를 모두 만족해야 승인한다. confidence는 통계적으로 보정된 확률이나 실측 정확도가 아니다.
- 업체 신원은 별도의 상호·주소·좌표/사진 설명 대조로 확인한다. AI가 같은 종류의 공간이라고 판단해도 특정 업체 사진이라는 증명은 아니다.
- 실제 제공처 후보에 내용 검사를 적용한다. 후기·등록 주체 불명 사진은 검사 미실행/오류/불확실이면 숨긴다. 이미지 서비스가 작동하지 않을 때도 등록 주체가 명시된 업체 사진과 기존 수동 검수 등록부는 유지한다. 모델이 명시적으로 무관하다고 판정한 업체 사진은 제외한다.
- 한 공급자당 후보 최대3장, 동시2건, 호출당5초/재시도0, 결과7일 캐시. 캐시는 모델·키 변경을 구분하며 키 원문을 저장하지 않는다. 인증/제한 오류는60초 회로 차단, 실패 사진은 승인으로 바꾸지 않는다. 기존 외부 호출 계측·시간당 예산을 사용한다.
- `PHOTO_VISUAL_CHECK=true`는 공유 양식에만 추가했다. 실제 `.env`나 키 값은 수정하지 않았다. 이미지 검사에는 공개 후보 이미지 URL과 장소명·사진 설명만 전송한다.
- 레저에서 신뢰할 수 있는 사진이1장이면1장만 표시하고 빈 두 번째 카드를 제거한다. 잘못된 이전 공개/블로그 캐시는 v7/v4로 분리했다.
