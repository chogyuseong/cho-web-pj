# 데이트 플랜 메뉴판·사진·지도 점검 (2026-10-25)

## 실제 확인 결과

후속 재점검: 사용자가 지도 키를 갱신한 뒤 현재 `.env`의 Client ID로 `127.0.0.1:8000`과 `localhost:8000`을 각각 검사했을 때 SDK HTTP 200, 지도 생성 성공, 인증 실패 없음으로 확인됐다. 반면 실행 중인 서버의 `/api/status`가 반환하는 지도 ID는 현재 `.env` 값과 달랐다. 키 내용은 출력하지 않고 일치 여부만 비교했다. 서버 설정 재반영을 위해 실행 중인 서버의 완전 종료·재시작이 필요하다.

- 최근 저장된 실제 코스의 3개 장소는 사진 API에서 각각 5장을 반환했다. 앞의 두 장소에 대해 Edge에서 원본·썸네일을 직접 열어 확인했으며, 일부 원본이 실패해도 해당 썸네일은 열렸다. 반환 개수와 이미지 표시 성공 여부는 별개다.
- 두 카페·식당의 메뉴 원문은 새로 조회해도 HTTP 403 응답이었다. 자료가 없다고 단정할 수 없으며 현재 서버에서 공급자가 조회를 허용하지 않은 상태다. 공원은 메뉴 조회 대상에서 제외했다.
- 지도 클라이언트 ID는 설정되어 있었다. `http://127.0.0.1:8000`에서 실제 SDK 로드·지도 객체 생성 이후 인증 실패 콜백이 발생했다. 네이버 콘솔의 Dynamic Map 사용 권한과 등록 웹 서비스 URL을 확인해야 한다. 이번 점검에서 계정 설정을 변경하지 않았다.
- 키·개인 입력·출발지·귀가지 좌표는 진단 출력에 포함하지 않았다.

## 수정

1. 코스에 포함된 카페·식당에도 메뉴 패널을 연결했다. 이전에는 주변 식당 카드에만 연결되어 있었다.
2. 가격이 있으면 메뉴판 이미지를 숨기던 분기를 분리했다. 같은 업체에 연결된 이미지가 확인된 경우 가격과 함께 유지한다. 파서 개선 이전 캐시는 새 버전 키로 분리했다.
3. 숨겨진 lazy 이미지가 로드 완료를 기다리며 계속 숨겨질 수 있는 경로를 수정했다. 패널 수준 지연 조회는 유지하고, 확인한 이미지 후보를 실제 `<img>`에 넣을 때는 eager로 로드한다.
4. 네이버 지도 인증 실패·키 누락 시 Leaflet 공개 지도로 대체한다. 장소 표시와 방문 순서는 제공하되 점선은 실제 길찾기 결과라고 표시하지 않는다. 배경 타일도 실패하면 개략도와 장소 링크를 제공한다.
5. 옵션 전환·재연결 시 기존 지도와 크기 관찰자를 정리한다.

## 검증 범위

메뉴 가격+메뉴판 동시 보존, 숨겨진 lazy 이미지 표시, 실제 코스 상세의 메뉴 패널, 지도 SDK 실패 시 대체 지도 표시, 반복 지도 재생성, 390/768/1440px 가로 넘침을 회귀 테스트로 확인한다. 브라우저 회귀 테스트의 공급자 응답·이미지·지도 타일은 고정 응답을 사용하며, 위의 실제 공급자 점검과 구분한다.

진단 명령 (`datemate` 폴더):

```powershell
.\.venv\Scripts\python.exe scripts/inspect_plan_assets.py --network --refresh
.\.venv\Scripts\python.exe scripts/inspect_plan_assets.py --network --probe
.\.venv\Scripts\python.exe scripts/inspect_plan_assets.py --map-probe
```

`--refresh`는 공개 메뉴를 새로 요청하고, `--probe`는 Edge로 이미지 후보를 확인한다. `--map-probe`는 별도 브라우저 컨텍스트에서 진단 문서를 가로채 두 접속 주소를 재현한다. 실제 서버를 중단하거나 같은 포트에 서버를 추가하지 않는다. `--live`는 실행 중인 서버의 공개 지도 ID가 현재 설정과 일치하는지 비교한다. 실제 사용자 데이터베이스는 읽기만 하되 공급자 조회 결과 캐시는 갱신한다.

화면 수정으로 공급자의 HTTP 403이나 지도 계정 인증을 해결했다고 주장하지 않는다. 메뉴 제한 시 원문 링크를 이용할 수 있고, 네이버 지도 인증 실패 시에는 공개 지도가 대체된다.
