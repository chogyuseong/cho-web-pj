- 원래 범위를 유지하려면 먼저 필요한 것: 뉴스 권한 활성화 여부 결정, 이름·기간 규칙 v1 을 이번 표본이 아닌 **새 표본**으로 재측정, 부산·지방 거점 보강, 약관 해석.

## 8. 1단계에서 확정할 구현 계약과 변경 파일 후보

1단계는 사용자가 지시할 때만 합니다. 아래는 축소안을 기준으로 한 제안이고, 원래 범위로 가면 묶기·상태 부분이 늘어납니다.

**서버**
- `GET /api/popups?region=&visit_date=&q=` (둘러보기는 `visit_date` 없이 한국시간 오늘). 응답: `status`(ready / empty / partial / unavailable / key_missing / disabled), 출처 목록(제목·요약 텍스트, URL, 출처 날짜, 기간 근거 문자열과 연도 확인 여부, 거점과 위치 등급, 직선거리), 실패한 검색원 목록.
- 캐시: 원본 후보 캐시 키 = `popups-raw:{RULES_VERSION}:{HUBS_VERSION}:{지역}:{정규화 검색어}:{sort}:{display}`. 성공 1시간, 결과 0건 10분(기존 `blog_search.py` 의 3600/600 과 같게), 실패는 캐시하지 않음. 방문일 상태는 캐시하지 않고 요청마다 다시 계산(7절). 거점 좌표는 `popup-hub-point:{HUBS_VERSION}:{hub_id}` 30일(약관 2-3 의 ② 확인 후 확정).
- 외부 요청 시간 제한 10초(기존과 같게). 요청당 외부 호출 상한: 블로그 1(+뉴스 1, 권한이 생기면) + 좌표 미캐시 거점 최대 3 = 4~5건. 재시도 없음.
- 동시 실행: 같은 캐시 키는 프로세스 안 잠금으로 한 번만 부르고, 기다림은 짧게(기존 `image_search._lock` 처럼 대기 후 실패 응답). 동시 외부 호출 최대 3.
- 제한: `web_security.EXPENSIVE` 에 `^GET /api/popups$` 등록 + 새 검색(캐시 없음)에만 `require_ip('popup-search', 'DATEMATE_IP_POPUP_SEARCHES_PER_MINUTE', 3, …)`. 근거: 새 검색 1회 최대 5건 × 분당 3회 = 시간당 최대 900건이라 이 값만으로는 제공자 IP 몫(기본 300/시간)을 넘을 수 있으므로, 시간당 상한(예: IP 대역당 시간 30회)을 함께 두는 안을 1단계 시작 때 수치로 확정.
- 끄는 스위치: `DATEMATE_POPUPS_ENABLED=0` 이면 API 는 `disabled`, 화면은 탭·구역을 그리지 않음.
- 뉴스를 쓰게 되면 `perf_trace.py` 종류 표에 `/search/v1/news` 추가(0-4 의 7).

**주변 코스 버튼 (0-4 의 1)**
- 축제 버튼은 출발지·지역을 바꾸고 방문일을 축제 기간 안으로 옮기며 `festival`(FestivalAnchor)을 저장합니다. 팝업 버튼은 **출발지(필요하면 시·도)만** 바꾸고 방문일·교통수단·취향은 유지하며, `festival` 필드에 싣지 않습니다.
- 기준점 필드 제안: **1단계에서는 추가하지 않음**. 근거: 출발지 이름("더현대 서울 주변", "성수 일대(대략) 주변")과 좌표만으로 코스 생성에 충분하고, 새 필드는 `models.py` 변경과 저장 코스 호환 검토가 필요합니다. 대가로 저장 코스를 다시 열었을 때 "어느 팝업을 골랐는지" 표시는 되살리지 못합니다. 필요해지면 `PopupAnchor`(id·source_url·lat·lon·level)를 별도 필드로 추가(DB 마이그레이션 없음, conditions JSON).
- 위치 미확인 출처: 버튼 비활성 + 이유. 동네 기준점: "이 일대 주변 코스 추천받기".

**화면**
- 상한: 축제처럼 카드 첫 6개 + "더 보기", 서버는 최대 30건. 지도는 같은 목록에서 위치 확인된 것만(축제 `mapItems` 와 같은 구조). 같은 거점의 여러 글은 마커 하나에 목록.
- 헤더(0-4 의 4): "다섯 번째 탭"과 "장소 둘러보기 안의 전환" 두 안을 320·390px 헤더 줄 수로 실측해 고름(현재 4개 메뉴도 320px 에서 둘째 줄).
- 적용 화면(0-4 의 5): 새 추천, 저장 코스 다시 열기, 새로고침 이어받기. `/shared` 제외.
- 단계(0-4 의 6): 1a 서버 API + 둘러보기 → 1b 코스 결과 구역 + 주변 코스 버튼 → 1c 지도 레이어, 단계마다 검사 보고.

**추출 규칙 v1 후보 (이번 표본으로 맞추지 말고 새 표본으로 재측정)**
