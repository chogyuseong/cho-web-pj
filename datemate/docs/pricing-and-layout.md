# 비용 검색과 옵션 배치

추천 요청이 들어오면 최종 후보 장소의 누락 단가를 네이버 블로그 검색에서 조회합니다. 모든 장소에 대량 요청하지 않으며 중복 장소를 합쳐 최대 3개 요청을 동시에 처리합니다. 검색 성공 결과는 1시간, 실패는 5분 캐시합니다. ‘현재 단가 다시 검색’은 캐시를 건너뛰고 재조회하고 인원별 비용과 조건 차이를 재계산합니다. 장소 교체 후보와 교체 완료 결과도 가격 조회를 반영합니다.

가격 출처는 다음처럼 구분합니다.

- 공식 등록 단가: 운영기관 자료에서 확인한 범위·확인일을 유지합니다. 모든 공식 페이지를 매 요청마다 자동 수집한 가격은 아닙니다.
- 웹 참고 단가: 장소명이 맞고 1년 이내 작성된 검색 결과에서 명시된 입장료·관람료 또는 대표 메뉴 단가를 가져옵니다. 원문·작성일·인용 근거를 표시합니다. 블로그 값이므로 공식 현재가로 확정하지 않습니다. 날짜별 무료 개방·개인 할인·연령·메뉴 선택으로 실제 결제 금액이 달라질 수 있습니다.
- 계획용 범위: 검색에서 가격을 확보하지 못했고 사용자가 허용한 경우에만 서비스의 명시된 1인 가정 범위를 사용합니다. 실제 단가가 아닙니다. ‘실제 단가 검색이 안 되면 계획용 예산 범위 사용’을 해제하면 값을 만들지 않습니다.

실제 검색 확인 예: 경복궁 입장료 3,000원 참고값을 네이버 검색 결과에서 원문·작성일과 함께 확보했습니다. 다른 장소의 현재 단가까지 확보했다는 의미는 아닙니다. 현재 키는 블로그 검색은 정상이며 웹문서·지역 검색은 401입니다. 네이버 지역 검색 자체에는 메뉴 가격이나 입장료·예약 잔여석이 제공되지 않으므로 모든 현재가를 보장할 수 없습니다.

인원·예산 입력 중에는 현재 코스의 단가로 비용 미리보기를 즉시 계산합니다. 새 장소 선택에 따른 가격 검색은 추천 또는 단가 재검색 시 실행합니다. 식사 후보는 기존과 같이 방문 수·시간·비용 합계에 미포함입니다.

‘조건 차이와 방문 준비’는 `state=unmet` 항목이 있을 때만 표시합니다. 미확인만 있는 코스에는 표시하지 않습니다. 가격 근거와 상태는 비용표에 계속 남습니다. ‘일정 살펴보기’ 버튼은 옵션 제목 바로 옆에 있고 상세 일정은 선택한 카드 바로 다음에 표시합니다. 상단 옵션 버튼으로 다른 코스로 전환할 수 있습니다.

검증: `scripts/check_pricing_layout_ui.py`에서 카드와 상세의 DOM 순서, 미확인만 있을 때 안내 비활성, 단가·합계 표시, 인원 입력 즉시 미리보기, 강제 재조회, 옵션 전환 및 JavaScript 오류 없음을 확인합니다. 결과는 `docs/pricing-layout-check.json`에 기록합니다.
