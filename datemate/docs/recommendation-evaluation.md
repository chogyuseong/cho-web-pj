# 추천 품질 검증 기준

자동 테스트 통과율은 사용자 만족도나 실제 영업 정확도가 아니다.

## 출시 전 수동 평가

서울 25개 구 × 카페·문화·실내 활동 3가지 = 75개 요청을 같은 날짜와 예산으로 비교한다.
기존 버전과 개선 버전의 옵션 3개를 순서를 섞어 평가한다. 최소 2명이 독립 평가하고 의견이 다른 항목은 재확인한다.
평가 기록에는 버전, 검색 시각, 지역, 요청, 장소의 공식 출처, 확인 날짜를 남긴다. 개인정보와 비밀키는 기록하지 않는다.

| 평가 항목 | 판정 방법 |
| --- | --- |
| 의도 일치 | 원한 활동이 포함되고 제외한 활동이 없는가 |
| 방문 가능성 | 업체 정체성·현재 주소·영업시간·휴무·예약을 원문에서 확인했는가 |
| 예산 | 인원과 1인/전체 예산을 구분했으며 가정 가격을 표시했는가 |
| 동선 | 실제 지도 경로로 방문·이동·대기 시간을 감당할 수 있는가 |
| 다양성 | 3개 옵션이 장소와 경험 양쪽에서 다른 선택지를 주는가 |
| 선택 의향 | 평가자가 실제로 고를 코스가 하나 이상 있는가 |

모르는 항목은 미확인으로 남기고 성공으로 세지 않는다. 날짜·분모·미확인 비율을 함께 보고한다.
실사용자에게는 코스 선택, 방문 후 불편, 재사용 의향을 수집한다. 기존 피드백 UI를 사용하고 실제 방문 인증으로 부르지 않는다.

## 자동 회귀 검사

`python -m pytest tests/test_intent_regressions.py tests/test_request_intent.py tests/test_course_search.py tests/test_evidence_quality.py`

금액 단위·인원 우선순위·조건부 날씨·제외 표현·검색 연결·부정 언급·협찬 표시·운영 자료 유효기간·메뉴 접근 제한을 검사한다.
합성 후보 기반 추천 검사는 `test_request_intent.py`, `test_option_diversity.py`, `test_condition_audit.py`를 함께 사용한다.

현재 실제 이용자 평가 75건은 수행하지 않았다. 공식 도보·대중교통 경로와 검증된 운영 데이터 공급처 연결이 추가로 필요하다.
