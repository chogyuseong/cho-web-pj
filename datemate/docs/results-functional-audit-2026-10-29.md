# 데이트 플랜 기능 점검 — 2026-10-29

## 발견한 문제와 수정

1. **레저 검색 서버 오류**: 실제 장소의 `address`가 `null`이면 지역 추출 정규식에서 예외가 발생했다. 빈 주소를 허용하고 사용자 선택 지역을 사용한다. 검색은 해당 방문지 좌표의 반경 1.5km를 유지한다.
2. **일부 스포츠 후보 누락과 대기**: 업체 분류가 `체육관`처럼 포괄적인 경우 구체 스포츠 상호를 놓쳤다. 스포츠 시설 분류와 종목 이름이 함께 일치할 때 보완하며 용품점은 제외한다. 6종목 검색을 최대 3개씩 병렬 실행하고 요청 계측 문맥을 유지한다. 이전 분류 결과 캐시와 새 결과를 분리한다.
3. **교체 후 확인 정보 누락**: 일반 교체·레저 교체·가격 재조회 저장 경로에서 확인 요약, 추천 요약, 검색 묶음, 되돌리기용 고정 상태가 일관되지 않았다. 공통 저장 처리에서 재계산하고 저장 직전 부모 존재와 고정 버전을 검사한다. 연결된 경로 공급자가 있으면 변경 동선도 재조회한다.
4. **늦은 응답이 다른 코스를 덮음**: 레저 선택·가격 재조회·되돌리기·초안 적용·제보 후 재조회가 현재 선택을 덮을 수 있었다. 응답이 속한 옵션만 갱신하고, 여전히 해당 옵션을 보고 있을 때 화면을 갱신한다. 이미 사라진 옵션의 응답이 전체 목록을 지우지 않는다.
5. **빠른 고정·교체 클릭**: 연속 고정 요청이 이전 상태로 덮일 수 있었다. 코스별 고정 요청을 순서대로 처리한다. 장소·레저 교체 중 중복 제출을 막는다.
6. **모달과 비용 차이 표시**: 늦은 식사 메뉴·미리보기·공동 선택 초안이 다른 창을 덮지 않도록 확인한다. 비용 차이는 불확실한 구간의 차이로 계산해 최솟값과 최댓값이 뒤집히지 않게 한다.
7. **검색 실패와 후보 없음 구분**: 네이버 권한·키/연결 문제, 주변 후보 없음, 시간·예산·필수 조건으로 제외된 경우를 구분한다. 실패 후 다시 찾기가 가능하고 고정한 방문지는 검색 대신 해제 안내를 표시한다.

## 실제 외부 연결과 한계

격리된 임시 DB에서 실제 네이버 검색 키를 사용해 종로 박물관 2곳의 샘플 일정으로 레저 검색을 실행했다. 수정 전 `address=None` 예외를 재현했고 수정 후 **1.17초, 주변 스포츠 10곳, 교체 가능한 후보 10곳**을 확인했다. 사용자 DB와 환경 파일은 변경하지 않았다.

브라우저 회귀 검사는 임시 저장소와 통제된 응답을 사용한다. 위 실제 네이버 검색 1건은 서울 전 지역·모든 외부 이미지·실제 영업·예약 가능성을 검증했다는 뜻이 아니다. TMAP 도보·대중교통 키가 없어 해당 공급자 실접속 검사는 수행하지 않았다.
