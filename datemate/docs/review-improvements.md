# 1~9 개선 기록

- 시작 경로: 기본 입력 폼으로 통합. 빠른 입력 중복 노출 제거.
- 결과: 선택 옵션의 조건 차이 중복 제거, 요약과 옵션 비교표 추가.
- 옵션: 기존 다양성 선택에 실제 활동·예산·이동·옵션1 대비 다른 장소 개수를 표시.
- 근거: 장소별 등록 주소, 추천 이유, 운영 자료 경과일, 검색 글 등장 여부, 가격 유형과 블로그 작성일·발췌를 표시. 주소 연결은 지점 검증 완료로 표현하지 않음. 기존 1년 이내 가격 인용과 90일 운영 자료 판단 유지.
- 필수 조건: 선택 설정에서 반드시 지킬 조건 노출. 기존 미확인/불일치 차단 및 제외 활동 보호 유지.
- 대기: 소유자별 비동기 작업 조회, 실제 검색/구성/가격 단계 표시. 가격 확인 중 코스 후보 미리 보기. 최종 조건 검사 뒤 확정. 사진·후기는 개별 로딩/재시도 경로 유지.
- 구조: 결과 렌더링, 진행 조회, 근거 표시를 별도 파일로 분리. 전역 상태 전체 제거 또는 프레임워크 전환까지 수행한 것은 아님.
- 추적: 요청 ID, 예외 스택, 총 처리 시간, 검색 작업별 단계 경과 시간. 요청 본문/키를 로그에 넣지 않음.
- 검사: 전체 회귀 184개 통과. 종로 실제 검색·질문10종·저장복원·390px UI 통과. 은평 실제 시나리오 별도 스크립트 제공.

## 운영 범위
검색 작업은 프로세스 메모리에 보관하며 최대 2개 실행/6개 대기 포함 활성, 완료 후 10분 보관. 단일 서버용이다. 재시작 시 작업은 사라지고 재검색 안내를 제공한다. 다중 인스턴스 배포 시 공유 작업 저장소/큐가 필요하다. 원문 데이터가 없는 메뉴·별점·실시간 운영 여부는 생성하지 않는다. 사용자 만족도나 방문 성공률은 실제 사용자 조사로 별도 평가해야 한다.

## 마무리 검증 (2026-10-23)

- 결과에는 선택 코스 상세 하나만 노출하고 비교표/옵션 버튼으로 전환한다. 가격 미확인과 계획용 가정 개수를 요약 카드에 명시한다.
- 상세 렌더링과 채팅 UI까지 별도 파일로 분리했다. 기존 모듈 호환을 위해 공용 상태는 유지한다.
- 입력 폼에서 구간/총 도보 제한, 가격 추정 허용을 직접 변경할 수 있다.
- 자유 입력 제외 활동은 모든 검색 완화 단계에서 유지한다. 회귀 검사 추가.
- 비동기 작업은 진행 상태·완료 결과를 SQLite에 1시간 보관한다. 검색 중 새로고침 시 기존 작업에 재연결한다. 동일 실행 요청은 같은 작업으로 합친다. 일시 조회 오류는 3회까지 재연결하며 실패 시 재검색 버튼을 제공한다.
- 서버가 중단된 미완료 작업은 자동 실행 재개가 아닌 명시적 재검색으로 복구한다. 완료 결과는 메모리에서 없어져도 저장소에서 조회한다. 다중 서버에서 작업을 실행하는 분산 큐는 여전히 별도 배포 설계 대상이다.
- 벡터 인덱스 내부 오류가 나면 같은 장소 범위의 저장 원문을 읽는다. 임의 장소나 생성 사실을 근거로 대체하지 않는다.
- 실서비스 API 대표 검사: 종로/은평/구로/성수 모두 추천 3개. 요청 위치·예산 보존, 근거 개수 및 필수 조건 차단을 검사했다. 결과는 live-acceptance.json에 기록했다. 네이버의 모든 업체·사진·가격을 검증했다는 뜻은 아니다.
- 실제 브라우저: 은평 검색 도중 새로고침 복원, 옵션2 전환과 상세 하나 유지, 잘못된 작업ID 실패 후 조건 화면 복귀, 390px 가로 넘침 없음. 종로 입력과 질문10종 및 대화 복원 검사도 통과.
- 정상/실패 작업, 타인 조회 차단, 메모리 소실 후 조회, 중복 검색 방지 테스트를 추가했다.

실제 사용자 만족도·방문 성공률은 사용자 피드백으로 측정해야 하며 코드 검사만으로 수치를 주장하지 않는다. 실제 메뉴/운영/사진 지점 일치가 원문에서 확인되지 않으면 미검증 상태를 유지한다.

## 중구 검색 점검
중구 기본 입력/카페 투어의 실제 추천 경로에서 각각 3개 코스를 확인했다. 기존 단계별 조건 완화와 필수 조건 차단을 유지했다. 새 근거 요약에서 course_search/search_adjustments/reasons/option_purpose가 명시적으로 null일 때 예외가 나는 결함을 수정하고 회귀 테스트를 추가했다. 사용자가 겪은 특정 실패가 이 결함 때문이었는지는 당시 예외 기록이 없어 확정하지 않는다. 이후 작업 실패 응답에는 실패 단계와 오류 번호를 넣어 로그와 연결한다.
