# 도로명 건물번호까지만 검색

app/search_address_text.py에서 검색용 주소를 공통 처리한다. 예: 코델 + 서울특별시 강서구 양천로401 4층비401호 → 코델 서울특별시 강서구 양천로401. 층·호·건물명·괄호주소는검색에서제외한다. 원래주소와좌표는저장/표시/업체대조에유지한다. 도로명이없으면지번번지까지, 그마저불명확하면구단위로검색한다. 숫자길(강남대로94길),건물부번401-2도보존한다.

메뉴: 가게이름+정리주소 우선, 같은주소+메뉴, 가게이름+구+메뉴 순서로 조회. 결과에 query_used를기록하며 기존 메뉴캐시v2는사용하지않는다.
공개사진: 같은정리주소 우선, 없으면구검색. 이미지API: 기존이름검색에같은정리주소의추가조회연결. 사용자사진검색링크도같은주소형식을사용한다. 이미지/공개사진캐시버전갱신.

이전코드도메뉴와공개사진검색에는층주소전체가아닌구이름위주를사용했다. 따라서모든누락이층주소탓이었다고판단하지않는다. 이번변경으로상세주소노이즈를배제하면서도로명으로정확히특정하도록했다.

실조회: 소문난성수감자탕 연무장길45→숫자메뉴8개. 스시도쿠카미동왕십리본점 왕십리로295→숫자메뉴11개(기존이미지메뉴형식에서검색결과변경). 브리즈밀 양평로22길18과우지커피불광중앙점 통일로755의사진정상조회·브라우저표시확인. 코델예시식당은업체가조회되지만확인한공개검색응답에는메뉴자료가없어금액을생성하지않았다.

이전미확보8곳도정리주소로재검사했지만이번조회에서사진미확보. 상세주소제거로모두해결됐다고표현하지않는다. 결과road-photo-recheck.json.
