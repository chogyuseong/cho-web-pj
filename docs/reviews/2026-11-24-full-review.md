### 참고(조치 불필요에 가까움) [코드]

- Worker 가 직접 내는 503·421·404·429(`cloudflare/edge.mjs:205-224`)에는 nosniff·CSP·HSTS 가 없습니다. 본문이 고정 문자열이라 악용 경로는 보이지 않습니다.
- CSP 는 `script-src` 에 네이버 도메인 전체, `style-src` 에 `'unsafe-inline'` 을 허용합니다. HTML 주입이 생기면 강한 방어선이 아니지만 지금은 주입 지점이 없습니다.

### 잘 막혀 있다고 확인한 것

- 소유자 검사: `/api/plans/{id}…` 와 `/api/chat/plan/{id}` 전 경로가 미들웨어(`main.py:267-276`)와 처리 함수에서 두 번 검사합니다. order-suggestion·reorder·delay-check·delay-recovery·transport·replace·leisure-select·meal-preview·agreement-preview·draft-apply·shares 포함, `tests/test_plan_owner_check.py` 목록에 빠진 경로 없음.
- 공유 링크: 토큰 `token_urlsafe(32)`, DB 에는 해시만, 24시간 만료. `public_plan` 은 허용 목록 방식이라 좌표·출발지·귀가지·요청 글·지연 기록·코스 id 가 나가지 않습니다. 의견은 장소 id 와 4개 값뿐이라 저장형 XSS 가 들어갈 곳이 없습니다.
- 프런트 XSS: 앱 코드에 `innerHTML`·`insertAdjacentHTML` 없음(Leaflet 제외). 링크는 http(s) 만 통과.
- Origin/CSRF·쿠키: 변경 요청의 Origin·`Sec-Fetch-Site` 검사, `__Host-` 쿠키(HttpOnly·Secure·SameSite=Lax), DB 에는 sha256 만, 본문 64KiB·15초 제한.
- 관리자 키: 헤더로만 받고 `hmac.compare_digest`, 실패 10회 10분 잠금.
- SSRF: `/photo-thumb` 는 서버가 내보낸 주소 허용 목록·https·호스트 제한·리다이렉트 금지·크기 상한. 사용자 입력 URL 을 서버가 가져오는 경로 없음.
- SQL: 값은 모두 `?` 바인딩.
- Cloudflare: Cache API 를 쓰지 않아 사용자별 응답이 섞일 곳이 없음. Worker 가 `x-forwarded-for` 를 지우고 `cf-connecting-ip` 로 다시 넣음.
- 동시 저장: 같은 부모에서 두 변경을 저장하면 형제 코스 두 개가 생길 뿐 되돌리기 체인은 깨지지 않습니다. 같은 초안 두 번 적용은 코스 하나(코드로 확인, 동시 실행 테스트는 하지 않음).

### D1. '지연 이어 가기'가 변경 경로마다 따로 구현돼 있다 [코드]

- 방향: '코스 + 저장된 기록 → 다시 계산한 코스' 한 함수(지연·중간 축제 자리·종료 허용·기록 이어 붙이기)를 두고 변경 경로가 그것만 부르게 합니다.

### D2. 코스 저장 경로가 둘이고 정리 규칙이 다르다 [코드]

- `plan_changes.save_change` 는 끊긴 수단 예외 정리·축제 변화 안내·필수 조건 검사·자동차 재확인을 하고, 식사·합의 초안(`experience.apply_draft`)은 직접 INSERT 합니다. A3 이 여기서 나옵니다.
- 장소 수와 `conditions.count` 의 관계도 경로마다 다릅니다(식사 추가는 맞추고 지각 복구 빼기는 그대로 둠). A2·A4 가 여기서 나옵니다.

### D3. 같은 판단의 중복 [코드]

- `delay_recovery._same_kind`(378-402) 와 `_options`(463-484) 의 후보 거르기 규칙이 복사돼 있습니다.
- 시각 글 ↔ 분 변환이 `planner.minutes/clock`, `festival_time._minutes/_clock`, `condition_audit` 안의 `mins`, `quality` 의 `mins` 로 나뉘어 있고 자정 처리만 서로 다릅니다(A5).
- 조사 붙이기가 서버(`leg_modes.josa`, `delay_recovery._ro`)와 화면(`delay-check.js delayRecoveryJosa`)에 따로 있습니다.

### D4. 테스트 빈틈 [코드]

- 지각 기록이 있는 코스에 대한 테스트는 '같은 번호에서 다시 복구'와 '기록 뒤의 다른 변경'만 봅니다. 다른 번호에서 다시 확인·복구(A1), 빼고 진행 뒤의 장소 바꾸기·레저(A2), 수단 예외가 있는 코스의 식사 추가(A3), 1곳 코스(A4), 자정 넘김(A5)은 없습니다.
- 프런트 단위 테스트가 없습니다. JS 테스트는 `cloudflare/*.test.mjs` 둘뿐이고 화면 로직은 Playwright UI 테스트 46개 파일에만 기대는데, 전체 26분이라 로컬에서 잘 돌리지 않게 됩니다(★ 절에도 '이 PC 에서 전체는 돌리지 않음'이 반복됨).
- 한도·남용 쪽: 제보가 다른 사용자 추천에 미치는 영향(S1), 접수 단계의 IP 별 작업 수(S2), 미리보기 경로의 한도(S3)를 고정하는 테스트가 없습니다.
