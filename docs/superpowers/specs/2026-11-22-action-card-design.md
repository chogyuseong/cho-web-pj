# 실행 카드(할 일 순서) — 설계 (2026-11-22, 짧은 설계)

## 왜
흩어진 확인 항목('네 가지 확인', 접힌 '장소별 확인 자료', 당일 도구)을 할 순서대로 한 장에 모은다(2026-11-13 구조 분석 제안 '실행 카드').
근거(사용자와 합의): 시점을 붙인 할 일(실행 의도, Gollwitzer & Sheeran 2006)이 더 잘 지켜지고, 체크리스트는 알면서 빠뜨리는 실수를 줄이며(Haynes 등 2009),
예약·휴무처럼 미리 해야 할 일은 당일엔 늦다(계획 오류, Buehler 등 1994). 앱에서 직접 검증된 효과는 아니다.

## 정한 것
- 위치: 코스 상세(plan-detail.js)의 '이대로 방문하기 전, 네 가지 확인' 바로 위, 제목 '할 일 순서'. 새 파일 static/action-card.js.
- 자료: 저장된 코스만 읽는다(서버 호출 없음, 당일 도구와 같은 원칙). 새 서버 코드 없음.
- 순서와 항목(시점 → 할 일):
  1. 지금·전날: 장소마다 verification.places[i].coverage.missing(영업시간·휴무일·예약·가격) 확인 한 줄, place.reservation === true 면 '예약하기' 한 줄,
     고른 축제가 있으면 개최·운영 시간 확인 한 줄.
  2. 출발 전: 맨 앞 축제가 있으면 축제 도착 시각, 아니면 코스 시작 시각에 출발 · 첫 장소 도착 시각.
  3. 장소마다 도착 전: 자동차로 도착하는 장소(legs[i].mode === 'car')는 주차장 확인(주차비는 계산에 없음).
  4. 마무리: day-of.js lastDepartureNote 와 같은 계산으로 귀가 출발 시각, 귀가가 없으면 종료 시각까지 마치기.
- 체크 표시: 항목마다 체크 상자. 이 브라우저 localStorage('datemate:action-card:<plan id>')에만 저장, 실패해도 화면은 동작(try/catch). 코스 id 가 없으면 저장 안 함.
- 하지 않는 것: 공유 화면 표시·상대와 체크 공유(서버 저장 필요), 알림·시계 연동, 새 외부 호출.

## 방법(고른 것)
화면에서 만든다(가). 서버가 만들어 plan 에 싣는 방법(나)은 테스트하기 쉽지만 저장 코스 모양이 바뀌고 예전 코스엔 없다 — 화면 계산이면 예전 코스도 바로 보인다.
