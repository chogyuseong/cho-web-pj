# 한 곳만 새로운 곳으로 — 설계 (2026-11-22)

## 왜
매번 비슷한 데이트가 지겨운 사람을 위해, 코스는 무난하게 두되 장소 한 곳만 그 사람이 평소 잘 안 가는 종류로 넣는다.
본인이 켠 경우에만 동작한다(2026-11-13 구조 분석 제안 '한 곳만 낯설게').

## 목표 / 하지 않을 것
- 목표: 조건 화면의 선택 항목 "한 곳은 새로운 곳으로"를 켜면, 코스 장소 가운데 한 곳을 '익숙한 종류' 밖의 종류로 채우고 왜 새로운지 보여 준다.
- 하지 않을 것: 켜지 않은 사람의 추천을 바꾸기, 다른 조건(테마·실내외·예산·식사·피할 활동)을 넘어서기,
  새 외부 호출, 로그인·방문 기록 수집.
- 실패로 볼 것: 새로운 곳 때문에 추천이 아예 안 나오거나 다른 필수 조건이 미충족이 되는 것.

## 방법 (고른 것: 가)
| | 방법 | 장단점 |
|---|---|---|
| **가 (선택)** | 조건 화면 선택 항목, 추천 탐색에서 반영 | 목적에 맞음. 탐색·조건 확인·화면을 고쳐 중간 크기 |
| 나 | 장소 카드 '새로운 곳으로 바꾸기' 버튼 | 가장 작지만 추천 자체는 그대로, 매번 직접 눌러야 함 |
| 다 | 3안 중 하나를 항상 '새로운 하루' | 원치 않는 사람도 바뀜, 3안 다양성 규칙과 충돌 |

## 정한 것
- **종류 단위**: 기존 묶음 `option_diversity.place_group` — 식사·카페·전시·관람(보기)·산책(걷기)·체험·놀이(하기)·휴식(쉬기). '기타'는 세지 않는다.
- **익숙한 종류(서버가 정함, 화면이 보낸 값은 버림)**: 이 브라우저(쿠키 owner)의 최근 추천 5번(같은 recommendation_group_id 의 안들 = 한 번,
  그 첫 안만 셈, parent 있는 바꾼 코스 제외)에서 3분의 1 이상에 나온 묶음. 추천 기록이 없으면 기본값 {식사, 카페}(흔한 데이트 구성)로 보고 그렇게 안내한다.
  (처음 설계는 '최근 코스 15개'였으나, 3안은 일부러 서로 다르게 고른 것이라 다 세면 추천 한 번 만에 거의 모든 종류가 익숙해져 바꿈 — 최종 검토 지적.)
  추천을 시작할 때(recommendation_service.generate) 한 번 계산해 조건(`fresh_familiar`)에 저장 — 다시 열기·장소 바꾸기도 같은 기준.
- **탐색**: 후보는 기존 조건으로 거른 그대로. 마지막 단계 정렬에서 '새로운 종류 장소 수'가 정확히 1인 조합을 앞세우고(0개 < 2개 이상 < 1개 순으로 불리),
  기존 앞쪽 키(요청 활동·식사 배치)보다 뒤, 선호 점수보다 앞에 둔다. 조합을 버리지 않는다 — 3안 선택의 '첫 안보다 덜 맞는 안 거르기'(fit_key)에는 넣지 않는다.
- **결과 표시**: 새로운 종류 장소가 있으면 `plan['fresh_place'] = {index, group, label}`.
  조건 확인 '새로운 곳 한 곳': 1곳이면 충족('○○(체험·놀이) — 최근 코스에 드물던 종류예요'), 0곳이면 '확인 필요'(이 동네 후보에 새로운 종류가 없음),
  2곳 이상이면 충족 + '새로운 종류가 n곳 들어갔어요'.
  코스 상세의 해당 장소 칸에 '새로운 곳' 꼬리표, 결과 카드에 한 줄.
- **조건 화면**: '식사·실내외·이동 세부 설정 (선택)' 안, 피드백 반영 체크 옆에 체크 상자 "한 곳은 평소와 다른 새로운 곳으로". 기본 꺼짐.

## 빌더에게 맡기는 것
- 정렬 키를 넣는 정확한 위치(planner.recommend_strict 의 tier/정렬)와 option_diversity 3안 선택이 이 순서를 지키는지 확인.
- 공유 화면에는 표시하지 않는다(장소 이름·시각만 공유하는 원칙 유지).
- 테스트: 익숙한 종류 계산(기록 없음/있음, 화면 값 무시), 1곳 조합 우선, 후보 없을 때 확인 필요, 다시 열기 동일, 화면 꼬리표.
