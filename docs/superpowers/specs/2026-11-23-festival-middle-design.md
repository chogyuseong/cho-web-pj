# 축제를 코스 중간에 두기 — 설계 (2026-11-23, 짧은 설계. 사용자 '모든 권한, 혼자 처리할 수 있는 최대한')

## 왜
고른 축제는 코스 맨 앞(68차, position 'first')이나 코스 끝(70차, 'last')에만 둘 수 있었다. 낮 축제(예: 11:30~13:00)에 코스가 오전부터
저녁까지면 맨 앞은 개막까지 60분 넘게 기다려야 하고, 끝은 이미 운영이 끝나 축제를 아예 넣지 못했다.

## 정한 것
- 배치(app/planner.evaluate): 기존 규칙을 먼저 그대로 돈다 — 맨 앞 고정(festival_slot) → 코스 끝(evening_window + last_slot).
  둘 다 아니고 축제 없이 짠 코스가 성공했을 때만, 같은 축제 창(late_opening 의 개막·종료)으로 장소 i 와 i+1 사이 자리를 앞에서부터 본다.
  자리마다 '장소 i 를 떠난 시각 + 행사장 구간(거리 추정, 외부 호출 없음) + 전환 여유'로 last_slot(개막까지 60분 이하 기다림, 운영 종료 안)을 먼저 따지고,
  통과한 자리만 실제로 다시 계산한다(구간 max_leg, 뒤 장소 영업, 종료 시간, 총 도보, 예산 — 기존 규칙 그대로). 처음 성공한 자리를 쓴다.
  못 찾으면 축제 없는 예전 결과 그대로. 맨 앞·끝이 맞는 코스는 결과가 한 글자도 바뀌지 않는다.
- 저장 모양: festival_visit = {…기존 필드, position:'middle', after:i, leg:{LEG_FIELDS}}. leg 는 들어가는 구간(장소 i → 행사장, plan['legs'] 밖 —
  'last' 와 같은 형식). 나오는 구간(행사장 → 장소 i+1)은 plan['legs'][i+1] 에 그대로 둔다('구간 k 는 장소 k 에 도착' 약속 유지).
  그 구간의 origin 이름은 '<축제> 행사장'.
- 수단 예외 키: 들어가는 구간 (장소 i id, 'festival') — festival_pair 확장, 요청의 festival 항목으로 바꾼다. 나오는 구간 ('festival', 장소 i+1 id) —
  leg_modes.endpoints 가 그 구간 번호에 이 키를 돌려 구간 번호(index)로 바꾼다. 수단을 바꿔도 같은 자리(after)에 강제로 계산하고(evaluate festival_after),
  못 맞추거나 자리가 바뀌면 409. 코스 끝 축제도 새 수단으로 자리가 바뀌면(끝 → 중간) 409(예전과 같은 '축제가 빠짐' 거절의 확장).
- 지각 확인: 장소 i 줄 뒤에 '축제 · …' 줄(festival:true)을 넣고 운영 종료를 넘기면 문제(kind 'festival'). 장소 i+1 부터 보면 축제가 끝난 시각에서 출발.
- 지각 복구: 같은 자리(바꾸기는 i, 빼기는 번호를 당긴 자리)로 강제로 다시 짜고, 그 자리에 못 두면 그 후보는 빼고 '중간 축제 시간에 맞출 수 없어요'.
  축제 시각이 늦어지는 것은 끝 축제처럼 허용. 장소 i 를 바꾸면 다음 지점은 행사장, 장소 i+1 을 바꾸면 앞 지점은 행사장.
- 화면: 지도(planSegments 가 장소 i → 행사장 → 장소 i+1), 코스 상세(장소 i 칸 뒤에 축제 칸 + '장소 i → 축제 행사장' 줄의 [수단 바꾸기]),
  공유 화면(장소 i 칸 뒤 축제 칸 — after 만 더 싣고 구간은 싣지 않음), 실행 카드('도착 전'에 행사장 도착 시각, 자동차면 행사장 주차),
  현장용 일정 글, 코스 카드 태그, 지각 확인 복구 줄 번호(축제 줄을 세지 않음).
- 외부 호출: 자리 찾기 사전 검사는 거리 추정만. 실제 계산은 기존 구간 계산(route_leg) 그대로라 자동차 실제 길찾기 확인 때는 'last' 처럼
  새 두 구간(장소 i→행사장, 행사장→장소 i+1)이 바뀐 장소 구간을 대신한다. 새 종류의 외부 호출은 없다.

## 하지 않는 것
- 축제를 두 번 넣기, 축제 뒤 순서 바꾸기, 맨 앞·끝이 맞는데 중간이 더 나은지 비교하기(회귀 방지로 앞·끝 우선 그대로).
- 지각 복구가 들어가는 구간의 저장값(자동차 실제 길찾기)을 지키기 — 'last' 와 같이 거리 추정으로 다시 계산.

## 되돌리기 영향(옛 코드가 'middle' 을 보면)
- 옛 planner 는 중간 축제를 모르고 다시 계산할 때(수단·장소 바꾸기) 축제 없이 짠다. 옛 화면·공유는 'last' 가 아니면 맨 앞으로 보아
  축제 칸을 첫 장소 앞에 그리고, 지각 확인은 축제 시간을 빼고 계산한다(저장된 시간표는 남음). 오류는 나지 않는다.
  ('festival', 장소 id) 수단 예외는 옛 planner 가 그 키를 찾지 않아 무시된다.
