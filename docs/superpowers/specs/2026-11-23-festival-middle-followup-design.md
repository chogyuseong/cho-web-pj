# 코스 중간 축제 후속 — 설계 (2026-11-23, 짧은 설계. 사용자 '권장대로 진행해')

## 왜
77차(feat/festival-middle) 검토에서 남긴 것 네 가지를 줄인다.
1. 장소 바꾸기·자동차 실제 길찾기 재확인은 축제 자리를 고정하지 않고 앞에서부터 다시 찾아, 자리가 옮겨지거나 빠질 수 있었다.
2. 그 재확인은 '축제 없는 코스 → 코스 끝 시도 → 중간 자리' 순서라, 결국 쓰지 않는 구간(장소 i → i+1, 마지막 장소 → 행사장)을
   실제 길찾기로 조회했다(코스당 최대 2건. 캐시는 같은 구간 300초 재사용뿐, 추천 직후 재확인에는 호출 상한이 없다).
3. 수단을 바꾸면 축제가 말없이 새로 들어갈 수 있었다(코스 끝 축제에도 있던 동작).
4. 운영에서 실제 코스로 눌러 본 적이 없었다.

## 정한 것
- 자리 먼저(1·2): `planner.evaluate(festival_hint=i)`. 그 자리에 먼저 두어 보고 맞으면 그대로 쓴다. 못 두면 실패하지 않고 예전 순서로 다시 찾는다
  (`festival_after` 는 '그 자리 아니면 실패'라 수단 바꾸기·지각 복구가 쓰고, hint 는 '되도록 그 자리'라 아래가 쓴다).
  hint 가 장소 사이가 아니거나 맨 앞 고정 조건이면 외부 호출 없이 바로 예전 순서로 넘어간다.
  - 쓰는 곳: 장소 바꾸기 후보(planner.replacements), 레저 후보(leisure.options), 장소 변경 저장의 자동차 재확인(plan_changes.save_change),
    추천 직후 자동차 재확인(recommendation_service._verify_car_routes), 합의 코스 재계산(experience.make_draft).
  - hint 값은 모두 `leg_modes.middle_after(plan)`(중간 축제가 없으면 None → 예전과 똑같이 동작).
- 알리기(1·3): `festival_time.change_note(before, after)` 가 한 줄을 만든다 — 새로 들어감 / 빠짐 / 자리 바뀜. 같은 자리에서 시각만 달라지면 None.
  `set_change_note(updated, original)` 이 `plan['festival_change']` 에 싣거나 지운다(앞선 변경의 안내가 남지 않게).
  - 싣는 곳: 장소 바꾸기 후보, 레저 후보(응답의 festival_change), 저장(save_change — 실제 길찾기 재확인 뒤 최종 모양 기준), 수단 바꾸기(apply_change).
  - 보이는 곳: 장소 바꾸기 후보 카드(place-dialog.js), 레저 후보 카드(leisure.js), 변경 뒤 코스 상세(plan-detail.js). 문구는 서버에서만 만든다.
  - 막지 않는다: 수단을 바꿔 축제가 들어가는 것은 사용자에게 이득일 수 있다. 빠지거나 옮겨지는 수단 변경은 77차에서 이미 409 로 거절한다.
- 운영 확인(4): 서울 '남산봉수의식 등 전통문화행사'(11:00~15:40), 2026-11-25 09:00~20:00 4곳 도보 — 결과는 배포-이어가기.txt 브랜치 기록.

## 하지 않는 것
- 식사 추가(experience 의 식당 끼워 넣기)에 hint 주기 — 장소 번호가 밀려 자리 계산이 따로 필요하다. 지금처럼 앞에서부터 다시 찾는다.
- hint 자리에 못 둘 때 생기는 조회 낭비 줄이기(그 시도에서 부른 구간은 버려진다 — 드문 경우).
- 축제가 그대로일 때 안내하기, 시각만 달라진 것 알리기(이동 시간 변화는 delta 가 이미 보여 준다).
- 화면 테스트 추가(안내는 서버가 만든 글을 그대로 적는 한 줄).

## 되돌리기 영향
- DB 마이그레이션 없음. 저장된 `festival_change` 키는 되돌린 화면이 읽지 않아 보이지 않을 뿐이다.
