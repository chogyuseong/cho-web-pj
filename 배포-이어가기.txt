2. 클론과 설치 (Windows PowerShell)
----------------------------------------------------------------------
git clone https://github.com/chogyuseong/cho-web-pj.git
cd cho-web-pj\datemate
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env

- requirements-dev.txt 는 실행용(requirements.txt)에 테스트 도구(pytest, pypdf, playwright 등)를 더한 것입니다.
  requirements.txt 는 운영 실행에 필요한 것만 담고 있어, 테스트를 돌리려면 dev 쪽이 필요합니다.
- 이후 모든 명령은 datemate 폴더에서, 가상환경의 파이썬(.\.venv\Scripts\python.exe)으로 실행합니다.
  시스템 파이썬에는 의존성이 없어 테스트가 실패합니다.
- Windows 스마트 앱 컨트롤이 켜진 컴퓨터에서는 가상환경의 일부 패키지(uuid_utils 등)가
  "애플리케이션 제어 정책에서 이 파일을 차단했습니다" 오류로 실행되지 않습니다. 그럴 때는 Docker 로 실행합니다
  (저장소 최상위에서): docker compose up --build -d → http://127.0.0.1:8000, 종료는 docker compose down.
  코드를 고치면 같은 명령으로 다시 빌드하고, .env 만 바꿨으면 docker compose up -d --force-recreate.
  테스트는 CI 처럼 python:3.12 컨테이너에서 requirements-dev.txt 와 playwright chromium 을 설치하고
  DATEMATE_BROWSER_CHANNEL=chromium 으로 pytest 를 실행합니다.
  (2026-11-13 에 작업한 컴퓨터에서는 가상환경이 차단 없이 설치·실행됐습니다.)
- 최상위 package.json 의 allowScripts 는 wrangler 가 쓰는 esbuild·workerd 의 설치 스크립트를 허용합니다.


3. 키 넣기 (datemate\.env)
----------------------------------------------------------------------
.env 는 Git에 올라가지 않습니다. 새 컴퓨터에서는 키를 직접 다시 넣어야 합니다.
기존 컴퓨터의 datemate\.env 를 안전한 방법으로 옮기거나, 아래 발급처에서 값을 다시 확인하세요.
값은 `이름=값` 형태로 넣습니다(따옴표로 감싸도 읽힙니다). 키 값을 이 문서나 Git에 적지 마세요.

  TOUR_API_KEY
    용도: 축제 조회 (한국관광공사)
    발급: 공공데이터포털(data.go.kr) → "한국관광공사_국문 관광정보 서비스_GW" 활용신청
    주의: 일반 인증키(Decoding)를 넣습니다. % 기호가 들어간 Encoding 키는 인증에 실패합니다. 무료.

  NAVER_SEARCH_CLIENT_ID / NAVER_SEARCH_CLIENT_SECRET
    용도: 장소(지역)·이미지·블로그 검색. 실제 장소 코스 추천, 장소 둘러보기, 레저 후보 조회에 필요
    발급: NAVER API HUB의 NAVER 검색. Application에서 지역·블로그·이미지 권한 활성화

  NAVER_MAPS_KEY_ID / NAVER_MAPS_KEY
    용도: 주소 검색, 역지오코딩, 자동차 길찾기 (서버에서 사용)
    발급: 네이버 클라우드 플랫폼 Maps. 가입 시 결제 수단 등록 필요, 사용량 과금(무료 제공량은 콘솔에서 확인)

  NAVER_MAPS_JS_KEY_ID
    용도: 브라우저에 네이버 지도 표시 (Dynamic Map)
    주의: 콘솔의 Web 서비스 URL에 접속 주소를 등록해야 합니다.
          로컬은 http://127.0.0.1:8000 과 http://localhost:8000, 배포 후에는 실제 https 주소.
          2026-11-13 에 로컬에서는 "네이버 지도 Open API 인증이 실패했습니다"가 나왔습니다(로컬 주소가 등록돼 있지 않은 것으로 보임).

  DATEMATE_OPTION_SELECTOR (선택)
    용도: 코스 3안을 고르는 방식. experience(기본) / shadow / place. 6-2 참고.

키가 없을 때의 동작
- 네이버 검색 키 없음: 실제 장소 검색 불가. "서울 가상 장소 데모" 모드로만 시연 가능
- 네이버 지도 JS 키 없음: 위치 선택 지도가 OpenStreetMap으로 대체됨
- TOUR_API_KEY 없음: 축제 구역에 "키 미설정" 안내만 표시, 코스 추천은 정상
- LLM 키(GMS_KEY)는 .env 에서 제거한 상태입니다. 조건 해석·질문 답변은 규칙 기반으로 동작하고,
  블로그 글에서 장소를 뽑는 검색과 후기 사진 내용 검사는 동작하지 않습니다.
  코드에는 연결부가 남아 있어 GMS_KEY / GMS_BASE_URL / GMS_MODEL 을 넣으면 다시 켜집니다.

6-2. 코스 3안을 고르는 방식
- 문제: 3안이 장소만 다르고 하루 구성(식사·카페·전시·산책·체험)은 같은 경우가 많았습니다.
- 탐색 단계(app/option_diversity.py composition_beam): 단계마다 상위 60개만 남길 때 한 구성이 자리를 독점하지 않게 했습니다.
  정렬 상위 절반은 그대로 두고, 남는 자리는 우선 등급이 같은 후보 안에서 구성마다 몇 개씩 먼저 넣습니다.
  평가 횟수와 빔 크기(60/40)는 그대로이고, 한 종류 집중(focus) 요청은 바꾸지 않습니다. 탐색 정렬에서 식사와 카페를 다른 활동으로 셉니다.
- 선택 단계: 환경변수 DATEMATE_OPTION_SELECTOR
  · experience (기본): 자리마다 ① 구성이나 이동이 이미 고른 모든 안과 다르고 장소도 2곳 이상 다른 안 → ② 구성이나 이동은 다르고
    장소가 1곳 이상 다른 안 → ③ 같은 구성에서 장소가 다른 안 순서로 찾습니다. 기준 코스(1안)보다 요청 조건에 덜 맞는 안,
    피할 활동이 들어간 안, 장소 집합이 같은 안은 고르지 않습니다. 그런 안밖에 없을 때만 3개보다 적게 보여 줍니다.
    이름은 실제 차이에서 붙습니다: "기준 코스", "산책 넣은 코스", "이동이 짧은 안", "같은 활동 · 다른 동선",
    ③으로 채운 안은 "같은 구성 · 다른 장소"와 "코스 1과 같은 구성에서 장소 2곳이 달라요".

    다시 짓습니다: 뺀 활동이 다르면 "전시·관람 대신 산책 넣은 코스", 활동이 같고 이동이 다르면 "산책 넣은 코스 · 더 짧은 이동"

6-5. 구간별 이동 수단
- 일정의 구간 줄 옆 [수단 바꾸기]로 그 구간만 도보·대중교통·자동차·자전거로 바꿉니다. 귀가 구간도 됩니다.
  일정 위 "이동 수단 한 번에 바꾸기"는 코스 전체 수단을 바꾸고 따로 고른 구간 설정을 지웁니다.
  바꾸면 그 코스만 다시 계산해 새 버전으로 저장하고, "수단 변경 되돌리기"로 돌아갑니다.
- 저장: 기본 수단(transport)은 그대로 두고 바꾼 구간만 conditions.leg_modes 에 {from, to, mode} 로 남깁니다(최대 6개).
  구간을 출발·도착 장소 id 로 찾으므로 장소를 교체하면 그 앞뒤 구간은 기본 수단으로 돌아갑니다. 새 추천은 이 값을 받지 않습니다.
- 경로: POST /api/plans/{id}/transport (본문 {default?, legs?: [{index, mode}]}). 영업시간·휴무·마지막 입장을 못 지키면 409 로 막고,
  종료 시각·구간 이동·총 도보 초과는 경고와 함께 저장합니다(필수로 고른 조건이면 막음. 장소 교체와 같은 규칙).
- 자동차 구간만 네이버 길찾기를 부릅니다(한 번 변경에 최대 6건). 조회에 실패하면 추정으로 바꾸고 그렇게 표시합니다.
  이 경로와 기존 /replace 는 자동차 구간이 있는 실제 장소 코스에서 같은 브라우저 5초 1회 제한을 받습니다.
- 차 위치는 계산에 넣지 않고 안내만 합니다("차는 ○○ 근처에 있어요. … 그 시간은 계산에 없어요."). 아무것도 막지 않습니다.
- 표기: 수단이 섞이면 "도보·자동차 34분". 지도는 자동차 실제 경로만 실선, 도보 짧은 점선, 그 밖 긴 점선.
- 한계: 주차 시간, 환승, 차가 있는 곳까지 돌아가는 시간, 택시 요금은 계산에 없습니다.

  바뀌었으면 datemate\.env 와 npx wrangler secret put TOUR_API_KEY 로 바꿉니다. 개발계정은 하루 1,000건 한도입니다.
- 한국관광콘텐츠랩 저작권 정책의 "콘텐츠 캐싱(로컬서버 저장방식) 금지"가 지금의 서버 캐시(축제 목록 1시간, 상세 24시간)에

  작업한 두 컴퓨터 모두 네트워크에서 PostgreSQL 포트(5432)가 막혀 있어 미리 시험할 수 없었습니다.

  (NOSUPERUSER NOCREATEDB NOCREATEROLE) ③ public 스키마의 테이블·시퀀스 소유권을 새 역할로 이전
  (앱이 시작할 때 마이그레이션으로 테이블을 바꾸므로 소유권이 필요) ④ 새 연결 주소로 앱 기동·전체 흐름 확인
  ⑤ 운영에 같은 절차 적용 후 npx wrangler secret put DATABASE_URL.

8. Cloudflare 운영 배포와 재배포 방법
----------------------------------------------------------------------
공개 주소: https://datemate.guseong-family.workers.dev
구성: Cloudflare Worker(cloudflare/worker.js) → Cloudflare Containers(Dockerfile) → Neon PostgreSQL
상세 절차: datemate/docs/cloudflare-deployment.md

이미 되어 있는 것
- Cloudflare Workers Paid 플랜 가입, Worker "datemate" 생성
- Neon 프로젝트 연결. 연결 문자열은 처음 설정한 컴퓨터의 저장소 최상위 .env.local 에만 있습니다(Git 제외).
  앱은 datemate/.env 만 읽으므로 로컬 실행은 SQLite 를 씁니다. 배포에는 .env.local 이 필요 없습니다.
- Worker Secret 8개 등록: PUBLIC_ORIGIN, DATABASE_URL(풀링을 거치지 않는 직접 연결 주소),
  NAVER_SEARCH_CLIENT_ID, NAVER_SEARCH_CLIENT_SECRET, NAVER_MAPS_KEY_ID, NAVER_MAPS_KEY,
  NAVER_MAPS_JS_KEY_ID, TOUR_API_KEY
- 네이버 클라우드 콘솔의 Dynamic Map Web 서비스 URL에 공개 주소 등록
- 컨테이너를 아시아에 띄우는 위치 힌트(worker.js 의 locationHint "apac").
  이것이 없으면 요청마다 2~3초가 걸리고 축제 조회가 시간 초과로 실패합니다.

코드를 고친 뒤 다시 배포하기 (저장소 최상위에서)
0) git status 가 깨끗한지 먼저 확인합니다. wrangler deploy 는 커밋이 아니라 지금 폴더의 파일로 이미지를 만듭니다.
   작업 중인 미커밋 파일이 있으면 그것까지 운영에 올라갑니다(2026-11-13 세 번째 배포에서 실제로 그랬습니다).
1) Docker Desktop 을 켭니다. 배포할 이미지를 만드는 데만 필요합니다.
2) 처음 쓰는 컴퓨터라면: npm install, 그리고 npx wrangler login (로그인 확인은 npx wrangler whoami)
3) git push origin main, 그다음 npx wrangler deploy
4) 새 버전은 떠 있던 컨테이너가 꺼진 뒤에야 응답에 나옵니다. 컨테이너는 한 번 뜨면 꺼질 때까지
   같은 이미지를 쓰고, 10분쯤 접속이 없어야 꺼집니다.
   - 배포할 때 컨테이너가 꺼져 있었으면 바로 반영됩니다.
   - 떠 있었으면 배포 후 10분 넘게 사이트에 접속하지 말고 기다린 뒤 확인하세요.
     반영됐는지 보려고 사이트를 계속 열어 보면 컨테이너가 깨어 있어 오히려 늦어집니다.
     (2026-11-13 에는 13분 동안 접속하지 않은 뒤 한 번 확인하는 방식으로 매번 반영을 확인했습니다.)
   - 사용자가 꾸준히 접속하는 시간대에는 반영이 한참 미뤄질 수 있습니다.
     배포 즉시 컨테이너를 교체하는 기능은 아직 없습니다.
   - npx wrangler deployments list 의 버전은 Worker 기준이라 컨테이너 교체 여부는 알 수 없습니다.
     새 버전에만 있는 정적 파일 내용이나 화면 문구, 동작으로 확인하세요.
   반영된 뒤 공개 주소에서 코스 추천·축제(요금)·장소 둘러보기·지도를 확인합니다.
   /readyz 와 /healthz 는 외부에서 404 가 정상입니다(내부 확인 전용). 외부에서는 /api/status 로 봅니다.
5) 배포한 커밋과 Worker 버전을 이 문서 맨 위 ★ 에 적습니다.

Secret 을 바꿀 때: npx wrangler secret put 이름  (값은 입력 창에 붙여 넣기. 채팅·Git·문서에 적지 않기)
주소를 바꿀 때: PUBLIC_ORIGIN Secret 과 네이버 콘솔의 Web 서비스 URL 을 함께 바꿉니다.
환경변수(예: DATEMATE_OPTION_SELECTOR, DATEMATE_IP_*)를 운영에 넣을 때: cloudflare/worker.js 의 startAndWait() 안 env 에
이름과 값을 추가한 뒤 재배포합니다.

운영 중 알아둘 것
- 10분쯤 접속이 없으면 컨테이너가 꺼지고, 다음 첫 접속은 20~40초 걸립니다.
- Neon 무료 플랜은 저장 용량과 월 사용 시간에 한도가 있습니다. Neon 콘솔의 Billing 에서 확인하세요.
- "요청이 많아요"가 자주 뜨면 요청 한도를 올려야 합니다. 한도 이름과 기본값은
  datemate/.env.example 의 DATEMATE_IP_* 항목에 있습니다. 운영에는 기본값이 적용돼 있습니다.
  같은 IP 를 함께 쓰는 사용자(학교·회사 와이파이 등)는 한도를 나눠 씁니다.
- 추천 1회의 외부 호출 상한은 DATEMATE_EXTERNAL_CALLS_PER_RECOMMENDATION(기본 60)입니다.
  레저 후보 조회는 지역 검색을 12건까지, 구간 수단 변경은 길찾기를 6건까지 씁니다.
- 레저 패널을 열면 찾은 운동 시설이 장소 목록에 7일간 저장됩니다. 기본 추천에는 쓰이지 않습니다(6-1).


9. Git 작업 방식
----------------------------------------------------------------------
- 기본 브랜치: main. 2026-11-13 의 작업은 main 에 바로 커밋했습니다.
