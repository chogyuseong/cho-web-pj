1. 준비물
----------------------------------------------------------------------
- Git
- Python 3.12 (Windows 기준 `py -3.12` 로 실행되는지 확인)
- Microsoft Edge (브라우저 테스트가 설치된 Edge를 사용합니다)
- Node.js (Cloudflare 배포 도구 wrangler를 쓸 때만 필요)


2. 클론과 설치 (Windows PowerShell)
----------------------------------------------------------------------
git clone https://github.com/chogyuseong/cho-web-pj.git
cd cho-web-pj\datemate
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env

- requirements-dev.txt 는 실행용(requirements.txt)에 테스트 도구(pytest, pypdf, playwright 등)를 더한 것입니다.
  requirements.txt 는 운영 실행에 필요한 것만 담고 있어, 테스트를 돌리려면 dev 쪽이 필요합니다.
- 이후 모든 명령은 datemate 폴더에서, 가상환경의 파이썬(.\.venv\Scripts\python.exe)으로 실행합니다.
  시스템 파이썬에는 의존성이 없어 테스트가 실패합니다.
- Windows 스마트 앱 컨트롤이 켜진 컴퓨터에서는 가상환경의 일부 패키지(uuid_utils 등)가
  "애플리케이션 제어 정책에서 이 파일을 차단했습니다" 오류로 실행되지 않습니다. 그럴 때는 Docker 로 실행합니다
  (저장소 최상위에서): docker compose up --build -d → http://127.0.0.1:8000, 종료는 docker compose down.
  코드를 고치면 같은 명령으로 다시 빌드하고, .env 만 바꿨으면 docker compose up -d --force-recreate.
  테스트는 CI 처럼 python:3.12 컨테이너에서 requirements-dev.txt 와 playwright chromium 을 설치하고
  DATEMATE_BROWSER_CHANNEL=chromium 으로 pytest 를 실행합니다.
- 최상위 package.json 의 allowScripts 는 wrangler 가 쓰는 esbuild·workerd 의 설치 스크립트를 허용합니다.


3. 키 넣기 (datemate\.env)
----------------------------------------------------------------------
.env 는 Git에 올라가지 않습니다. 새 컴퓨터에서는 키를 직접 다시 넣어야 합니다.
기존 컴퓨터의 datemate\.env 를 안전한 방법으로 옮기거나, 아래 발급처에서 값을 다시 확인하세요.
값은 따옴표 없이 `이름=값` 형태로 넣습니다. 키 값을 이 문서나 Git에 적지 마세요.

  TOUR_API_KEY
    용도: 축제 조회 (한국관광공사)
    발급: 공공데이터포털(data.go.kr) → "한국관광공사_국문 관광정보 서비스_GW" 활용신청
    주의: 일반 인증키(Decoding)를 넣습니다. % 기호가 들어간 Encoding 키는 인증에 실패합니다. 무료.

  NAVER_SEARCH_CLIENT_ID / NAVER_SEARCH_CLIENT_SECRET
    용도: 장소(지역)·이미지·블로그 검색. 실제 장소 코스 추천과 장소 둘러보기에 필요
    발급: NAVER API HUB의 NAVER 검색. Application에서 지역·블로그·이미지 권한 활성화

  NAVER_MAPS_KEY_ID / NAVER_MAPS_KEY
    용도: 주소 검색, 역지오코딩, 자동차 길찾기 (서버에서 사용)
    발급: 네이버 클라우드 플랫폼 Maps. 가입 시 결제 수단 등록 필요, 사용량 과금(무료 제공량은 콘솔에서 확인)

  NAVER_MAPS_JS_KEY_ID
    용도: 브라우저에 네이버 지도 표시 (Dynamic Map)
    주의: 콘솔의 Web 서비스 URL에 접속 주소를 등록해야 합니다.
          로컬은 http://127.0.0.1:8000 과 http://localhost:8000, 배포 후에는 실제 https 주소.

키가 없을 때의 동작
- 네이버 검색 키 없음: 실제 장소 검색 불가. "서울 가상 장소 데모" 모드로만 시연 가능
- 네이버 지도 JS 키 없음: 위치 선택 지도가 OpenStreetMap으로 대체됨
- TOUR_API_KEY 없음: 축제 구역에 "키 미설정" 안내만 표시, 코스 추천은 정상
- LLM 키(GMS_KEY)는 .env 에서 제거한 상태입니다. 조건 해석·질문 답변은 규칙 기반으로 동작하고,
  블로그 글에서 장소를 뽑는 검색과 후기 사진 내용 검사는 동작하지 않습니다.
  코드에는 연결부가 남아 있어 GMS_KEY / GMS_BASE_URL / GMS_MODEL 을 넣으면 다시 켜집니다.


4. 실행
----------------------------------------------------------------------
.\.venv\Scripts\python.exe scripts/index_data.py --mode demo
.\.venv\Scripts\python.exe scripts/index_data.py --mode real
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

- 화면: http://127.0.0.1:8000
- 키·연결 상태: http://127.0.0.1:8000/api/status
- 색인 두 줄은 처음 한 번만 실행하면 됩니다. runtime 폴더(DB·캐시·색인)는 Git에 없어 새로 만들어집니다.
- .env 를 바꾸면 서버를 재시작해야 반영됩니다.

넣은 키가 실제로 동작하는지 한 번에 확인 (키 값은 출력하지 않음, 제공자별 1회 호출):
.\.venv\Scripts\python.exe scripts/check_external_integrations.py


5. 테스트
----------------------------------------------------------------------
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider

- 약 5분 걸립니다. 브라우저 테스트가 포함되어 Edge가 필요합니다.
- 테스트는 임시 저장소를 쓰고 외부 키를 비워서 실제 API를 호출하지 않습니다.
- 프런트 JS 포맷 점검: .\.venv\Scripts\python.exe scripts/format_sources.py --check
  (걸리면 --check 없이 실행해 정리)

8. Cloudflare 운영 배포 (완료) 와 재배포 방법
----------------------------------------------------------------------
공개 주소: https://datemate.guseong-family.workers.dev
구성: Cloudflare Worker(cloudflare/worker.js) → Cloudflare Containers(Dockerfile) → Neon PostgreSQL
상세 절차: datemate/docs/cloudflare-deployment.md

이미 되어 있는 것
- Cloudflare Workers Paid 플랜 가입, Worker "datemate" 생성
- Neon 프로젝트 연결. 연결 문자열은 저장소 최상위 .env.local 에 있습니다(Git 제외, 이 컴퓨터에만 있음).
  앱은 datemate/.env 만 읽으므로 로컬 실행은 계속 SQLite 를 씁니다.
- Worker Secret 8개 등록: PUBLIC_ORIGIN, DATABASE_URL(풀링을 거치지 않는 직접 연결 주소),
  NAVER_SEARCH_CLIENT_ID, NAVER_SEARCH_CLIENT_SECRET, NAVER_MAPS_KEY_ID, NAVER_MAPS_KEY,
  NAVER_MAPS_JS_KEY_ID, TOUR_API_KEY
- 네이버 클라우드 콘솔의 Dynamic Map Web 서비스 URL에 공개 주소 등록
- 컨테이너를 아시아에 띄우는 위치 힌트(worker.js 의 locationHint "apac").
  이것이 없으면 요청마다 2~3초가 걸리고 축제 조회가 시간 초과로 실패합니다.

코드를 고친 뒤 다시 배포하기 (저장소 최상위에서)
1) Docker Desktop 을 켭니다. 배포할 이미지를 만드는 데만 필요합니다.
2) 처음 쓰는 컴퓨터라면: npm install, 그리고 npx wrangler login
3) npx wrangler deploy
4) 새 버전은 떠 있던 컨테이너가 꺼진 뒤에야 응답에 나옵니다. 컨테이너는 한 번 뜨면 꺼질 때까지
   같은 이미지를 쓰고, 10분쯤 접속이 없어야 꺼집니다.
   - 배포할 때 컨테이너가 꺼져 있었으면 바로 반영됩니다.
   - 떠 있었으면 배포 후 10분 넘게 사이트에 접속하지 말고 기다린 뒤 확인하세요.
     반영됐는지 보려고 사이트를 계속 열어 보면 컨테이너가 깨어 있어 오히려 늦어집니다.
     (2026-11-12 두 번째 배포: 30초마다 확인하는 동안 10분 넘게 이전 화면이 나왔고,
      11분 30초 접속을 끊은 뒤 새 버전이 나왔습니다.)
   - 사용자가 꾸준히 접속하는 시간대에는 반영이 한참 미뤄질 수 있습니다.
     배포 즉시 컨테이너를 교체하는 기능은 아직 없습니다.
   - npx wrangler deployments list 의 버전은 Worker 기준이라 컨테이너 교체 여부는 알 수 없습니다.
     새 버전에만 있는 정적 파일이나 화면 문구로 확인하세요.
   반영된 뒤 공개 주소에서 코스 추천·축제(요금)·장소 둘러보기·지도를 확인합니다.
   /readyz 와 /healthz 는 외부에서 404 가 정상입니다(내부 확인 전용).

Secret 을 바꿀 때: npx wrangler secret put 이름  (값은 입력 창에 붙여 넣기. 채팅·Git·문서에 적지 않기)
주소를 바꿀 때: PUBLIC_ORIGIN Secret 과 네이버 콘솔의 Web 서비스 URL 을 함께 바꿉니다.

운영 중 알아둘 것
- 10분쯤 접속이 없으면 컨테이너가 꺼지고, 다음 첫 접속은 20~40초 걸립니다.
- Neon 무료 플랜은 저장 용량과 월 사용 시간에 한도가 있습니다. Neon 콘솔의 Billing 에서 확인하세요.
- "요청이 많아요"가 자주 뜨면 요청 한도를 올려야 합니다. 한도 이름과 기본값은
  datemate/.env.example 의 DATEMATE_IP_* 항목에 있습니다. 운영에는 기본값이 적용돼 있고,
  바꾸려면 cloudflare/worker.js 의 startAndWait() 안 env 에 해당 이름과 값을 추가한 뒤 재배포합니다.
  같은 IP 를 함께 쓰는 사용자(학교·회사 와이파이 등)는 한도를 나눠 씁니다.
